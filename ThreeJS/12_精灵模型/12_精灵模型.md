## 1. 精灵是什么

**要解决的问题：** 有些东西希望从任何角度看都是正面，比如头顶的标签、一颗光点、一滴雨。普通的 Mesh 做不到，换个角度就会看到侧面。

**一句话结论：** 精灵 `Sprite` 是一个**永远正对相机的平面**。相机怎么转，它就跟着转，看到的永远是正面（这种效果叫"广告牌效应 billboarding"）。

**最小代码：**

```js
import * as THREE from "three";

// 精灵：只需要材质，不需要几何体（它本身就是一个平面）
const spriteMaterial = new THREE.SpriteMaterial({ color: 0xffffff });
const sprite = new THREE.Sprite(spriteMaterial);
sprite.scale.set(100, 100, 1);

const group = new THREE.Group();
group.add(sprite);
export default group;
```

**和 Mesh 的区别：**

| | Sprite（精灵） | Mesh（普通模型） |
|---|---|---|
| 创建 | 只要材质 | 几何体 + 材质 |
| 朝向 | 永远正对相机 | 固定，会看到侧面、顶部、底部 |
| 形状 | 只能是一个平面 | 任意形状（立方体、球体、加载的模型） |
| 光照 | `SpriteMaterial` 不受光照影响 | 看材质（如 Lambert、Standard 受光照影响） |
| 适合 | 标签、光点、雨雪、粒子、远处的树 | 建筑、角色、地面等实体 |

简单说：要一张**永远正对你的图片**，用 Sprite；要一个**有体积、有不同侧面**的物体，用 Mesh。

**坑：**
- 精灵只能是平面，别指望它从侧面看有厚度。

## 2. 精灵有多大

**要解决的问题：** `new THREE.Sprite()` 时没传几何体，那它到底多大？

**一句话结论：** 精灵自带一个 **1 × 1** 的正方形平面（three.js 源码里顶点是 -0.5 到 0.5），所以 **`scale` 是多少，精灵就是多大**。

**最小代码：**

```js
sprite.scale.set(20, 20, 1);   // 1×1 放大 20 倍 → 20 × 20
sprite.scale.set(0.5, 0.5, 1); // → 0.5 × 0.5
```

**坑：**
- 第三个值（z）写什么都没影响，平面没有厚度。写 `scale.set(20, 20, 20)` 也能用，只是第三个 20 不起作用。

## 3. 用正投影相机验证大小（正投影相机填充）

**要解决的问题：** 第 2 步说 scale 20 就是 20 大，怎么亲眼确认？

**一句话结论：** 用一台**上下正好看到 20 高**的正投影相机，放一个 scale 20 的精灵，它会刚好上下填满画布。这说明 scale 就是**世界坐标里的尺寸**。

**代入数字算一遍：**
- 正投影相机没有近大远小，`top` 到 `bottom` 是多少，画面上下就能看到多少
- `s = 10`：top = 10、bottom = -10，上下一共 **20**
- 精灵 scale 20 → 20 高 → **上下刚好填满**；scale 10 → 只占上下的**一半**
- 左右：画面宽高比 k，左右能看到 `2 × s × k`。k = 1.6 时是 32，精灵 20 宽，左右会留空

**最小代码：**

```js
// 正投影相机：上下能看到 2 × s = 20
const k = width / height;
const s = 10;
const camera = new THREE.OrthographicCamera(-s * k, s * k, s, -s, 1, 8000);
camera.position.set(0, 0, 200);
camera.lookAt(0, 0, 0);
```

```js
// 精灵：20 × 20
const sprite = new THREE.Sprite(new THREE.SpriteMaterial({ color: 0xffffff }));
sprite.scale.set(20, 20, 1);
sprite.position.set(0, 0, 0); // 默认就是 (0,0,0)
```

**坑：**
- 用透视相机做这个实验看不准，因为透视相机近大远小，相机离得远近会改变精灵在画面上的大小。

## 4. 用精灵标注场景（贴图）

**要解决的问题：** 在模型头顶放一个光点或图标，从任何角度看都是正面（第 1 步精灵的特点）。

**一句话结论：** 标注就是三件事：**贴图、大小、位置**。

### 4.1 贴图

精灵材质的 `transparent` **默认就是 true**，png 贴图透明的部分会自动隐藏，不用手动开。

```js
const texture = new THREE.TextureLoader().load("./assets/光点.png");
const spriteMaterial = new THREE.SpriteMaterial({ map: texture });
```

### 4.2 颜色和贴图混合

同时设置 `color` 和 `map` 时，颜色会和贴图**相乘**：白色光点乘红色，就变成红色光点。

```js
const spriteMaterial = new THREE.SpriteMaterial({
  map: texture,
  color: 0x00ffff, // 贴图颜色 × 青色
});
```

Mesh 的材质（如 `MeshBasicMaterial`、`MeshLambertMaterial`）同时设 `color` 和 `map` 时，**也是相乘**，不是只能二选一。

### 4.3 大小

不用很精确，和要标注的物体**差不多一个数量级**就行，再按效果微调。物体 25 × 100 × 50，光点设 10 × 10 合适。

### 4.4 位置

**代入数字算一遍：** 把光点贴在立方体顶上

- `geometry.translate(0, 50, 0)`：100 高的立方体整体往上挪 50，底面在 y = 0，**顶面在 y = 100**
- 精灵 10 高，中心放在 y = 105，上下各 5，**底边在 105 − 5 = 100**，刚好贴着顶面

**最小代码：**

```js
import * as THREE from "three";

// 立方体：底面 y = 0，顶面 y = 100
const geometry = new THREE.BoxGeometry(25, 100, 50);
geometry.translate(0, 50, 0);
const mesh = new THREE.Mesh(geometry, new THREE.MeshLambertMaterial({ color: 0x00ffff }));

// 光点：10 × 10，中心 105 → 底边 100
const texture = new THREE.TextureLoader().load("./assets/光点.png");
const sprite = new THREE.Sprite(new THREE.SpriteMaterial({ map: texture }));
sprite.scale.set(10, 10, 1);
sprite.position.set(0, 105, 0);

const group = new THREE.Group();
group.add(mesh, sprite);
export default group;
```

**坑：**
- 精灵的 `position` 是它的**中心点**。想让它底边贴着物体顶面，中心要再往上加半个高度。
- 标注太大会挡住模型，太小又看不见。先按数量级设一个，再调 `scale`。

## 5. 用精灵模拟下雨下雪

**要解决的问题：** 一个精灵会做了，下雨就是**很多个精灵 + 每帧往下移**。

### 5.1 随机撒在一个区域里

**代入数字理解：**
- `Math.random()`：0 ~ 1
- `Math.random() - 0.5`：-0.5 ~ 0.5
- 乘 1000：-500 ~ 500

所以雨下在 x、z 各 1000 宽（-500 ~ 500）、高 0 ~ 600 的区域里。

```js
const RAIN_TOP = 600;
const spriteMaterial = new THREE.SpriteMaterial({
  map: new THREE.TextureLoader().load("./assets/雨滴.png"),
});

for (let i = 0; i < 16000; i++) {
  const sprite = new THREE.Sprite(spriteMaterial); // 共享同一个材质，节省内存
  sprite.scale.set(0.5, 0.5, 1);
  sprite.position.set(
    1000 * (Math.random() - 0.5), // x：-500 ~ 500
    RAIN_TOP * Math.random(),     // y：0 ~ 600
    1000 * (Math.random() - 0.5)  // z：-500 ~ 500
  );
  rainGroup.add(sprite);
}
```

### 5.2 每帧往下移

**一句话结论：** 每帧移动距离 = 速度 × 两帧之间过了多少秒。这样雨在任何电脑上都是同样的速度。

**代入数字理解：**
- 每秒 60 帧：每帧约 1/60 ≈ 0.0167 秒，速度 60 → 每帧落约 **1**
- 每秒 30 帧：每帧约 0.033 秒 → 每帧落约 **2**
- 两种情况下，一秒都落 **60**

```js
const clock = new THREE.Clock();
function loop() {
  const t = clock.getDelta(); // 距离上一次调用过了多少秒
  rainGroup.children.forEach((sprite) => {
    sprite.position.y -= t * 60;   // 每秒落 60
    if (sprite.position.y < 0) {
      sprite.position.y = RAIN_TOP; // 落地后回到顶部重新下
    }
  });
  requestAnimationFrame(loop);
}
loop();
```

**坑：**
- **出生高度和重生高度要一致。** 出生时用 `1000 * Math.random()`（0 ~ 1000），落地却回到 600：开头一段时间 600 ~ 1000 的雨还在落，落过一轮后雨只剩 0 ~ 600，前后不一致。统一用一个常量 `RAIN_TOP`。
- 不乘 `t`，直接每帧减固定值，雨速会跟着帧率变：快的电脑下得快，慢的电脑下得慢。

## 6. 下雨的两个问题

### 6.1 为什么用精灵，不用 Mesh

**一句话结论：** 雨滴又小又多又快，精灵顶点少、不算光照，又永远正对相机，看起来足够以假乱真。这是用一点点视觉真实度，换来大量性能的做法。

**① 顶点数（代入数字）：**
- 一个 Sprite 是 2 个三角形组成的矩形，**4 个顶点**
- 一个最简单的 3D 雨滴（小球、椭球），也要几十到上百个顶点
- 10,000 个雨滴：Sprite 是 10,000 × 4 = **40,000** 个顶点；Mesh 按每个 100 顶点算是 10,000 × 100 = **1,000,000** 个顶点，差 **25 倍**

**② 光照计算：**
- `SpriteMaterial` 不受光照影响，基本就是把贴图画到平面上
- `MeshStandardMaterial`、`MeshPhongMaterial` 等要为每个光源计算漫反射、高光等，开销大
- 成千上万个快速移动的雨滴，精确算光照几乎看不出区别，纯属浪费

**③ 视觉欺骗：**
- 雨滴又小又快，人眼分不出是 3D 模型还是一张图
- 只要平面永远正对镜头（精灵的特点），效果就足够了

**坑：**
- 每个 Sprite 都是一个**独立物体**，渲染器要一个一个单独画。本章场景实测，`renderer.info.render.calls`（这一帧画了几次）约 **940 次**（16000 个里只有落在画面内的才画）。所以雨滴数量也不能无限加。

### 6.2 为什么 near 要设大一点

**要解决的问题：** 相机在 `(92, 113, 85)`，雨下在 x、z 为 -500 ~ 500、y 为 0 ~ 600 的区域里，**相机就站在雨里面**，身边随时会有雨滴落过。透视相机近大远小，贴着相机的雨滴会被放得很大，看起来很奇怪（能看清雨滴的贴图）。

**一句话结论：** 透视相机的 `near` 表示"离相机比 near 还近的东西不画"。把 near 设成 10，离相机不到 10 的雨滴就不画了。

**代入数字算一遍：** 相机视野 90°，距离 d 处画面上下能看到 `2 × d × tan45° = 2d` 高

| 雨滴离相机 | 画面上下能看到 | 0.5 的雨滴占画面上下的比例 |
|---|---|---|
| 2 | 4 | 0.5 ÷ 4 = **1/8**，很显眼的长条 |
| 10 | 20 | 0.5 ÷ 20 = 1/40 |
| 150（大部分雨滴） | 300 | 0.5 ÷ 300 ≈ 1/600，几乎看不见 |

**最小代码：**

```js
// 第三个参数就是 near
const camera = new THREE.PerspectiveCamera(90, width / height, 10, 3000);
```

![image-20250704112159591](./assets/image-20250704112159591.png)

**坑：**
- near 也不能太大，否则离相机较近的正常模型也会被切掉。按场景尺寸设：本章场景几百大，near = 10 合适。
