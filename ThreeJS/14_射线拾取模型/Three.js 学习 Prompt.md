我在复习自己整理的 Three.js 入门笔记。每节有 Markdown、示例代码，有时还有模型和图片。优先使用我提供的本地目录和文件。仓库镜像在 [Three.js 入门笔记](https://github.com/Zenitsu-Tiger/ThreeJS-rumen-dao-titong/tree/main/ThreeJS)。我的目标是快速理解、记住主线，并能用自己的话解释代码。

## 每节先检查代码，再更新文档

1. 读取本节 Markdown、示例入口和相关模块，核对依赖版本、图片、模型资源，以及文档与代码是否一致。
2. 判断示例是否需要修复、更新或优化。有明确问题时，先直接在原文件中做必要改动。保持原教学目标，优先修复运行、版本兼容与数据顺序问题。代码通过完整入口运行，改完给我文件路径和简短改动说明。如果无法编辑文件，提供完整可运行的文件内容并说明限制。示例合适时保留现有实现。
3. 运行改后的示例，再以最新代码为准更新 Markdown。涉及实际模型的名称、层级、数量、返回结果和画面时，先从代码、资产或运行结果验证。明确区分已验证的计算、浏览器实跑效果和预期结果。版本有差异时说明使用了哪个版本。
4. 代码问题、文档纠错和优化说明放在简短的交付摘要里。范围限定在本节，除非我另外要求。

- 开头放最多五步的路线图，每步写清用到上一步的什么。每个知识点按「一句话结论 → 最小可运行代码 → 一个常见的坑」组织。代码有前置文件或依赖时写清楚。

## 我主动要求讲解时

开头先给最多五步路线图，每步写明与前一步的关系。除非我要求整节讲完或一次讲完剩余内容，每次一个知识点，讲完等我说「继续」。每个知识点按以下六步讲。

1. **先看效果。** 先给实际渲染图或可拖动的演示。空间、方向、形状相关内容必须有画面，演示代码要实际跑过。
2. **一句话说明问题。** 用一句话说清它要解决什么问题。术语第一次出现时，先用大白话定义。
3. **给最小可运行代码。** 使用本节真实 API、变量和数据。说明代码放在哪个文件，或交代独立运行所需的前置条件。
4. **逐行解释因果。** 逐层说明数据从哪来、什么时候可用、这一行为什么需要、它改变了什么、哪个后续步骤用到它、删掉它有什么后果。关键行讲细，能直接承接的行简讲。数值按「它是什么 → 为什么需要 → 用在哪行 → 最后才算」展开，推导一行一步。
5. **讲一个最容易遇到的坑。** 用原例展示坑在哪里、由哪行触发、会出现什么结果。
6. **总结并承接。** 用一句话收束，并指出这个知识点用到了上一点的什么。

逐行解释示范。遇到 `if (!obj) return;`，先核对原例实际执行顺序，然后讲完整因果。模型异步加载 → 点击时 `getObjectByName()` 可能返回 `undefined` → 未拦截时描边通道收到 `[undefined]` → 渲染遍历时报错 → 如果下一帧在 `composer.render()` 后安排，错误会阻止下一帧注册。最后指出这行只结束当前选择操作，从而保护渲染循环。缩短其他背景也要保留这条因果链。

解释函数时，区分传入参数、函数对已有对象的修改、函数返回值，以及 `if` 的判断。比如 `Ray.intersectTriangle(..., true, frontPoint)` 中，`true` 是正面命中开关，`frontPoint` 是提前创建的目标对象。成功时写入并返回该对象，失败时返回 `null`，对象保留原值。讲这类问题时分别展示命中与未命中的结果，再说明应检查哪个变量。
