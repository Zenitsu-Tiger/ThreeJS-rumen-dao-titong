# 02 · 标签位置的设置方法

上一节我们把标签和模型同级放在同一个坐标上。实际项目里，模型往往嵌套在多层分组（`Group`）里，或者我们需要把标签精准贴在模型的某个局部位置（比如圆锥尖顶）。本节基于 Three.js `0.174.0` 的 `01_同步tag坐标.js` 和 `mesh.js`，讲清**世界坐标同步**、**父子继承**和**几何体顶点定位**三种设置标签位置的方法。

## 路线图

1. 分清模型的本地坐标与世界坐标，学会用 `getWorldPosition()` 或 `mesh.add(tag)` 把标签对齐到受父级位移影响的模型中心。
2. 在第 1 步 `mesh.add(tag)` 的局部坐标系下，读取 `geometry.attributes.position` 顶点坐标，把标签精准钉在模型特定部位（如圆锥尖顶）。

## 1. 世界坐标与本地坐标：让标签对齐模型中心

**一句话结论**　`mesh.position` 只是相对父对象的**本地坐标**；当父对象移动时，想把同级标签对齐到模型，必须用 `mesh.getWorldPosition()` 取**世界坐标**，或者直接 `mesh.add(tag)` 继承父级位置。

**关键参数与变量先看清**

* `mesh.position.set(50, 0, 50)`：`mesh` 相对父节点 `meshGroup` 的**本地坐标**。无论 `meshGroup` 怎么移动，打印 `mesh.position` 永远是 `(50, 0, 50)`。
* `meshGroup.position.x = -100`：父分组的偏移量，会带着内部的 `mesh` 一起沿 X 轴向左移动 100。
* `mesh.getWorldPosition(worldPosition)`：Three.js 内部会先自动更新祖先链的世界矩阵（`updateWorldMatrix(true, false)`），再把 `mesh` 在整个场景里的真实坐标写入预先创建的 `worldPosition`（`THREE.Vector3`）中。

**最小可运行代码**（来自 `01_同步tag坐标.js`，入口仍为 `index.html` + `index.js`）

```js
import * as THREE from 'three';
import { CSS2DObject } from 'three/addons/renderers/CSS2DRenderer.js';

const geometry = new THREE.BoxGeometry(40, 40, 40);
const material = new THREE.MeshLambertMaterial({ color: 0x00ffff });

const mesh = new THREE.Mesh(geometry, material);
mesh.position.set(50, 0, 50);

const meshGroup = new THREE.Group();
meshGroup.add(mesh);
// mesh 位置受到父对象局部坐标 .position 影响
meshGroup.position.x = -100;

const group = new THREE.Group();
const div = document.getElementById('tag');
const tag = new CSS2DObject(div);

// 1）获取 mesh 的世界坐标
const worldPosition = new THREE.Vector3();
mesh.getWorldPosition(worldPosition);
console.log('worldPosition', worldPosition); // (-50, 0, 50)

// 2）把世界坐标复制给同级 tag，使其与 mesh 重合
tag.position.copy(worldPosition);
group.add(meshGroup);
group.add(tag);

console.log('mesh.position', mesh.position); // 依然是 (50, 0, 50)
export default group;
```

**数值推导（为什么世界坐标 x 是 `-50`）**

```text
mesh 本地坐标       = (50, 0, 50)
meshGroup 父级偏移  = (-100, 0, 0)
mesh 世界坐标 x     = -100 + 50
                    = -50
mesh 世界坐标       = (-50, 0, 50)
```

**三种写法对比（✅ 正例 vs ⚠️ 局限 vs ❌ 反例）**

```js
// ✅ 推荐（动态跟随）：直接挂成子节点，自动继承 mesh 和 meshGroup 的全部位移/旋转
mesh.add(tag); // tag 默认局部坐标 (0, 0, 0)，正好落在 mesh 中心

// ⚠️ 可用但有局限（静态快照）：用世界坐标对齐同级标签
mesh.getWorldPosition(worldPosition);
tag.position.copy(worldPosition);
group.add(tag);
// 局限：这只复制了“这一刻”的坐标；如果后面 meshGroup 移动，tag 不会跟着走

// ❌ 反例：把本地坐标当世界坐标抄给同级 tag
tag.position.copy(mesh.position); // 抄到了 (50, 0, 50)，漏算了父级 -100 的偏移
group.add(tag);
// 结果：立方体在 (-50, 0, 50)，标签却跑到 (50, 0, 50)，两者相差 100 单位
```

**坑**　把 `tag` 挂在 `group`（或 `scene`）下时，直接抄 `mesh.position` 会丢失所有父节点的位移；即使改用 `getWorldPosition()`，也只是一次性拷贝，物体动起来后标签会留在原地。想让标签跟着模型走，优先用 `mesh.add(tag)`。

## 2. 标记几何体顶点：把标签钉在模型局部特征点

**一句话结论**　先把标签挂到模型下（`mesh.add(tag)`），再从 `geometry.attributes.position` 读出目标顶点的局部坐标赋给 `tag.position`，就能把标签精准钉在几何体的某个顶点上。

**关键参数先看清**

* `new THREE.ConeGeometry(40, 70, 64)`：创建一个底面半径 `40`、高 `70`、圆周分段 `64` 的圆锥体。它的局部几何中心在 `(0, 0, 0)`，因此底面在 $y = -35$，**尖顶在 $y = +35$**。
* `geometry.attributes.position`：存放几何体所有顶点**局部坐标**的缓冲区属性（`BufferAttribute`）。
* `pos.getX(0), pos.getY(0), pos.getZ(0)`：读取索引为 `0` 的第 1 个顶点的 $x, y, z$。对 `ConeGeometry(40, 70, 64)` 来说，索引 `0` 正好是圆锥尖顶 `(0, 35, 0)`。

**最小可运行代码**（来自 `mesh.js`）

```js
import * as THREE from 'three';
import { CSS2DObject } from 'three/addons/renderers/CSS2DRenderer.js';

const geometry = new THREE.ConeGeometry(40, 70, 64);
const material = new THREE.MeshLambertMaterial({ color: 0x00ffff });

const mesh = new THREE.Mesh(geometry, material);
mesh.position.set(50, 0, 50);

const meshGroup = new THREE.Group();
meshGroup.position.x = -100;

const group = new THREE.Group();
const div = document.getElementById('tag');
const tag = new CSS2DObject(div);

// 1）先让 tag 成为 mesh 的子节点，共享 mesh 的局部坐标系
mesh.add(tag);

// 2）读取几何体第 0 号顶点的局部坐标（圆锥尖顶），设为 tag 的局部位置
const pos = geometry.attributes.position;
tag.position.set(pos.getX(0), pos.getY(0), pos.getZ(0));

meshGroup.add(mesh);
group.add(meshGroup);

export default group;
```

**正反例对比（为什么必须配合 `mesh.add(tag)`）**

```js
// ✅ 正例：tag 挂在 mesh 下，直接吃几何体顶点的局部坐标 (0, 35, 0)
mesh.add(tag);
tag.position.set(pos.getX(0), pos.getY(0), pos.getZ(0));
// 最终世界位置 = meshGroup(-100,0,0) + mesh(50,0,50) + tag(0,35,0) = (-50, 35, 50)（圆锥尖顶）

// ❌ 反例：tag 挂在 group 下，却直接填顶点局部坐标
group.add(tag);
tag.position.set(pos.getX(0), pos.getY(0), pos.getZ(0));
// 结果：tag 跑到了世界坐标 (0, 35, 0)，完全脱离了在 (-50, 0, 50) 的圆锥
```

**坑**　`geometry.attributes.position` 里存的是**几何体自身的局部坐标**，不包含 `mesh.position` 和父分组偏移。如果忘了 `mesh.add(tag)` 而把标签挂在外部 `group` / `scene` 下，标签会直接飞回世界原点附近。

## 速记

| 场景需求                           | 核心写法                                                     | 坐标性质               |
| ---------------------------------- | ------------------------------------------------------------ | ---------------------- |
| 模型有父级位移，同级放标签（静态） | `mesh.getWorldPosition(v)` + `tag.position.copy(v)`          | 世界坐标（一次性快照） |
| 标签放在模型中心且随模型移动       | `mesh.add(tag)`（`tag.position` 默认 `(0,0,0)`）             | 局部坐标（自动继承）   |
| 标签钉在几何体某个具体顶点         | `mesh.add(tag)` + `geometry.attributes.position.getX/Y/Z(i)` | 局部坐标（自动继承）   |

## 自测

1. `meshGroup.position.x = -100`，`mesh.position.set(50, 0, 50)` 且 `meshGroup.add(mesh)`。此时 `mesh.position.x` 和 `mesh.getWorldPosition(v)` 得到的 `v.x` 分别是多少？
2. 同样是把标签放到 `mesh` 中心，`tag.position.copy(worldPosition)` 挂到 `group` 下，和直接 `mesh.add(tag)`，在后续移动 `meshGroup` 时有什么区别？
3. 在 `mesh.js` 中，`geometry` 是 `ConeGeometry(40, 70, 64)`。为什么把 `pos.getX(0), pos.getY(0), pos.getZ(0)` 赋给 `tag.position` 前，必须先执行 `mesh.add(tag)`？

<details>
<summary>查看答案</summary>


1. `mesh.position.x` 是本地坐标 `50`（不受父对象移动影响）；`v.x` 是世界坐标 `-50`（`-100 + 50`）。
2. `tag.position.copy(worldPosition)` 只是复制了当时的世界坐标，后续 `meshGroup` 移动时标签留在原地；`mesh.add(tag)` 让标签成为子节点，会自动跟随 `mesh` 和 `meshGroup` 一起移动。
3. `geometry.attributes.position` 里存的是相对几何体中心的局部坐标（本例顶点 0 为 `(0, 35, 0)`）。只有先 `mesh.add(tag)` 让标签进入 `mesh` 的局部坐标系，这组坐标才会准确落在圆锥尖顶；否则标签会跑到世界坐标 `(0, 35, 0)`。
