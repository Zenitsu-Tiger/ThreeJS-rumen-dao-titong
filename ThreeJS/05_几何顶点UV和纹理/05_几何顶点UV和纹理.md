# 05 几何顶点 UV 和纹理

> 本章主线：**图片怎么贴到几何体上**（UV）→ **怎么改变贴的方式**（repeat / offset / wrap）→ **多种贴图叠加**（复合纹理）→ **场景氛围**（HDR 环境贴图、雾）。
>
> 全章只需要记住一个公式，UV 相关的现象都能用它推出来：
>
> ```text
> 采样坐标 = 几何体UV × repeat + offset，超出 [0,1] 的部分交给 wrap 处理
> ```

## 一、纹理贴图基础

### 1. 加载图片 → 赋给 map（01）

```js
const geometry = new THREE.SphereGeometry(100, 30, 30);
const texture = new THREE.TextureLoader().load('/earth.jpg'); // 返回 THREE.Texture

const material = new THREE.MeshLambertMaterial({
  map: texture, // 颜色贴图
});
```

- 球体自带的 UV 是把整张图**横向绕一圈、纵向从南极到北极**铺上去的，所以一张 2:1 的世界地图刚好能包成地球。
- 换成 `MeshLambertMaterial` 这类受光照影响的材质，场景里必须有光源，否则贴图是黑的。

### 2. 加载是异步的

`load()` **立刻**返回一个 Texture，但图片要等下载完才填进去，渲染循环会在图片到位后自动显示。需要在加载完成时做事，用 `load` 的回调参数（03）：

```js
const texture = textureLoader.load(
  '/earth.jpg',
  tex => console.log('加载成功', tex.image.width, tex.image.height), // onLoad
  undefined,                                                       // onProgress
  err => console.error('加载失败', err),                            // onError
);
```

> 注意：06 里写的 `texture.onLoad = function () {}` 和 `texture.onError = ...` **不会触发**。Texture 对象上没有这两个属性，回调必须作为 `load()` 的参数传入。

### 3. 透明 png（02）

```js
const geometry = new THREE.PlaneGeometry(50, 50);
const texture = new THREE.TextureLoader().load('/转弯.png');

const material = new THREE.MeshBasicMaterial({
  map: texture,
  transparent: true, // 不开的话，png 的透明部分会显示成实色
});

const mesh = new THREE.Mesh(geometry, material);
mesh.rotateX(-Math.PI / 2); // 平面默认竖着（在 XY 平面），转 -90° 平躺成地面
```

- 平面默认**只有正面可见**。转成地面后从下往上看是看不到的，需要两面都可见时加 `side: THREE.DoubleSide`（06 用了）。

### 4. 资源路径（Vite）

| 放置位置         | 写法                    | 说明                         |
| ---------------- | ----------------------- | ---------------------------- |
| `public/` 目录   | `'/earth.jpg'`          | 以 `/` 开头，打包后路径不变，推荐 |
| `src/assets/`    | `'/src/assets/xxx.png'` | 开发时能用，**打包后会失效** |

02 里的 `'../public/转弯.png'` 应改成 `'/转弯.png'`。

## 二、UV 坐标

### 1. UV 是什么

UV 是**贴图上的坐标**，用来告诉 Three.js：几何体的**某个顶点**对应**图片上的哪个位置**。

- `u`：图片宽度方向（横向），0 → 1
- `v`：图片高度方向（纵向），0 → 1
- 用的是**比例**而不是像素，所以与图片分辨率无关

```text
  v
  1 ┌─────────────┐ (1,1)
    │             │
    │    图片     │
    │             │
  0 └─────────────┘
  (0,0)          1  u
  左下角是原点，右上角是 (1,1)
```

### 2. UV 和顶点的对应关系

UV 与 `position` 一样，是几何体 `attributes` 里的一个属性，**按顶点顺序一一对应**：

| 属性                  | 每个顶点几个数 | BufferAttribute 第二个参数 |
| --------------------- | -------------- | -------------------------- |
| `attributes.position` | 3 个（x,y,z）  | `3`                        |
| `attributes.uv`       | 2 个（u,v）    | `2`                        |

### 3. 手写 UV：把一张图完整贴到矩形上（03）

```js
const geometry = new THREE.BufferGeometry();

// 4 个顶点位置（一个 160×80 的矩形）
const vertices = new Float32Array([
  0,   0,  0, // 顶点0 左下
  160, 0,  0, // 顶点1 右下
  160, 80, 0, // 顶点2 右上
  0,   80, 0, // 顶点3 左上
]);
geometry.attributes.position = new THREE.BufferAttribute(vertices, 3);

// 索引：两个三角形拼成矩形
geometry.index = new THREE.BufferAttribute(new Uint16Array([0, 1, 2, 0, 2, 3]), 1);

// 4 个顶点的 UV：顶点在矩形的哪个角，就对应图片的哪个角
const uvs = new Float32Array([
  0, 0, // 顶点0 → 图片左下角
  1, 0, // 顶点1 → 图片右下角
  1, 1, // 顶点2 → 图片右上角
  0, 1, // 顶点3 → 图片左上角
]);
geometry.attributes.uv = new THREE.BufferAttribute(uvs, 2);

const texture = new THREE.TextureLoader().load('/earth.jpg');
const material = new THREE.MeshLambertMaterial({ map: texture });
const mesh = new THREE.Mesh(geometry, material);
```

> 改 UV 就能改“贴图的哪一部分”。例如把 UV 全部改成 0~0.5，矩形上就只显示图片的**左下 1/4**（被放大铺满）。
>
> 矩形是 2:1（160×80），地球图也是 2:1，所以不会变形。图片比例和几何体比例不一致时，贴图就会被拉伸。

### 4. 渲染时发生了什么

1. **顶点阶段**：每个顶点的 `position` 和 `uv` 一起传给顶点着色器
2. **光栅化**：GPU 对三角形内部的每个像素（片元）**插值**，算出各自的 UV
3. **片元阶段**：片元着色器拿着这个 UV 去 `map` 纹理里取颜色，输出到屏幕

所以只需要给**顶点**定义 UV，三角形内部的 UV 由 GPU 自动插值得到。

### 5. UV 的“自动裁剪”（04）

```js
const geometry = new THREE.CircleGeometry(100, 32);
console.log('uv', geometry.attributes.uv); // 可以看到圆形几何体自带的 UV
const texture = new THREE.TextureLoader().load('/436853.jpg');
const mesh = new THREE.Mesh(geometry, new THREE.MeshLambertMaterial({ map: texture }));
```

效果：图片被“裁”成了圆形，四个角显示不出来。

**原因：** 这并不是 Three.js 主动做了裁剪，而是 `CircleGeometry` 的 UV **本身就只分布在 [0,1] 方框内的一个内切圆里**。圆外的图片区域没有任何顶点去采样，自然就显示不出来。

```text
  ┌─────────────┐
  │ ╭───────╮   │   ← 整张图片 (0~1)
  │ │ 被采样 │   │
  │ ╰───────╯   │   ← 圆形 UV 只覆盖这部分
  └─────────────┘     四个角没人采样 → 看不到
```

![image-20250606172037807](./README.assets/image-20250606172037807.png)

> 结论：**几何体的 UV 覆盖图片的哪部分，就显示哪部分。** Three.js 不会把图片“尽量完整地塞进”几何体。

## 三、核心公式：repeat、offset、wrap 的关系

Three.js 在着色器里采样纹理前，会先对 UV 做一次变换：

```text
采样UV = 几何体UV × repeat + offset
```

| 属性                     | 作用                                     | 默认值             |
| ------------------------ | ---------------------------------------- | ------------------ |
| `texture.repeat`         | **缩放** UV（放大几倍）                  | `(1, 1)`           |
| `texture.offset`         | **平移** UV                              | `(0, 0)`           |
| `texture.wrapS / wrapT`  | 采样 UV **超出 [0,1]** 时怎么取值        | `ClampToEdgeWrapping` |

三者的分工：

- `repeat` 和 `offset` **一定会生效**，它们只负责算出采样坐标
- `wrap` 只决定**超出 [0,1] 的那部分**显示什么
- 几何体本身的 UV、顶点都**没有被修改**，变的只是“去图片哪里取颜色”

---

## 四、wrap 模式：超出 [0,1] 怎么办

- `wrapS` 控制 **U 方向**（横向），`wrapT` 控制 **V 方向**（纵向），需要分别设置

| 模式                           | 超出部分的处理               | 例：u = 1.3 实际采样 | 视觉效果         |
| ------------------------------ | ---------------------------- | -------------------- | ---------------- |
| `ClampToEdgeWrapping`（默认）  | 钳制到 0 或 1                | 1.0                  | 边缘像素被拉伸   |
| `RepeatWrapping`               | 只取小数部分                 | 0.3                  | 平铺重复         |
| `MirroredRepeatWrapping`       | 取小数部分，并每隔一次翻转   | 0.7                  | 镜像平铺         |

```js
texture.wrapS = THREE.RepeatWrapping; // U 方向平铺
texture.wrapT = THREE.RepeatWrapping; // V 方向平铺
```

> 注意：如果贴图是透明 png，而且边缘本身是透明的，那么 ClampToEdge 拉伸出来的也是透明像素，看起来就像“空出来了”。实际上那部分是被拉伸的边缘，不是空白。

## 五、repeat：贴图阵列（平铺）

### 1. 基本用法

```js
texture.wrapS = THREE.RepeatWrapping;
texture.wrapT = THREE.RepeatWrapping;
texture.repeat.set(12, 12); // U、V 方向各平铺 12 次
```

套公式推一下：几何体 UV 是 0 → 1，乘以 12 后变成 0 → 12；RepeatWrapping 只取小数部分，于是图片从头循环 12 次，形成 12×12 的阵列。

### 2. 只设 repeat、不设 wrap 会怎样？

**repeat 照样生效**，只是超出部分被钳制，看不到平铺：

```js
texture.repeat.x = 50;
// 不设 wrapS：采样 U 变成 0~50
//   → 只有平面最左边 1/50 是一张完整的图
//   → 其余 49/50 都是图片右边缘像素被拉伸
// 设了 wrapS = RepeatWrapping：
//   → 超出部分取小数，图片平铺 50 次
```

> 所以 **repeat + RepeatWrapping 要搭配使用**，才能得到平铺效果。

### 3. 平铺了，为什么图案还是被拉扁？

```js
const geometry = new THREE.PlaneGeometry(200, 20); // 宽:高 = 10:1
texture.repeat.set(2, 2);
```

关键在于：**平铺几次由 repeat 决定，每一份被拉成什么形状由几何体尺寸决定。**

- `PlaneGeometry` 的默认 UV：宽 200 对应 U 的 0→1，高 20 对应 V 的 0→1
- `repeat(2, 2)` 后，每一份贴图占 `(200/2) × (20/2) = 100 × 10`，仍然是 10:1
- 一张正方形图片被塞进 10:1 的格子，必然被拉扁

**解决办法：让 repeat 的比例跟几何体的宽高比一致**

```js
// 平面 200×20（10:1），图片是正方形
texture.repeat.set(10, 1); // 每一份是 20×20，正方形不变形
```

05 代码里只设 `repeat.x = 50`、不动 y，就是这个思路：长条平面只需要沿长边平铺。

### 4. 应用场景

- **地面、墙面、顶棚**：用一小张地砖、草地纹理平铺，不需要超大分辨率的图片，省显存
- 配合自定义 UV：UV 本身写成超过 1 的值，也能平铺

## 六、offset：平移贴图 / UV 动画

### 1. 方向：offset 为正，贴图往反方向移

```js
texture.offset.x = 0.5;
```

套公式（repeat 为 1）：

| 平面上的位置      | 几何体 u | 采样 u = u + 0.5 | 显示的内容           |
| ----------------- | -------- | ---------------- | -------------------- |
| 最左边            | 0        | 0.5              | 图片**中间**         |
| 中间              | 0.5      | 1.0              | 图片**右边缘**       |
| 右半边            | 0.5 ~ 1  | 1.0 ~ 1.5        | **超出范围**，交给 wrap |

结论：

- `offset.x = 0.5` → 图片的右半部分出现在平面的左半边，**贴图向左移动 50%，右边超出范围**
- `offset.y = 0.5` → 同理，**贴图向下移动 50%，上方超出范围**

可以这样记：**offset 移动的是“取景框”，取景框往右移，看到的画面就往左走。**

超出范围的部分：

- 默认 ClampToEdge：边缘像素被拉伸
- `RepeatWrapping`：接上图片开头，无缝衔接

### 2. repeat + offset 一起用

```js
texture.repeat.set(2, 2);
texture.offset.set(0.5, 0.5);
// 某顶点 UV (0.2, 0.6)
// 采样 U = 0.2 × 2 + 0.5 = 0.9  → 在 [0,1] 内，直接采样
// 采样 V = 0.6 × 2 + 0.5 = 1.7  → 超出，看 wrapT（Repeat 时取 0.7）
```

**顺序：先乘 repeat，再加 offset。**

![image-20250609103240809](./README.assets/image-20250609103240809.png)

### 3. UV 动画（05 + main）

05 把 texture 一起导出，就是为了让 main 的渲染循环能改它。每帧改 offset，配合 RepeatWrapping，贴图就会持续滚动，常用于流水、传送带、道路箭头等效果：

```js
// 05_纹理的偏移和缩放.js
texture.repeat.x = 50;
texture.wrapS = THREE.RepeatWrapping;
export { mesh, texture };

// main.js
import { mesh, texture } from './05_纹理的偏移和缩放.js';

function render() {
  texture.offset.x += 0.01; // 贴图持续向左滚动（想向右就用 -= ）
  renderer.render(scene, camera);
  requestAnimationFrame(render);
}
```

> 必须开 RepeatWrapping，否则 offset 越加越大，很快整个平面都变成拉伸的边缘像素。

## 七、UV 什么时候会超出 [0,1]？

| 情况                         | 会超出吗 | 说明                                      |
| ---------------------------- | -------- | ----------------------------------------- |
| 内置几何体 + 默认设置        | 不会     | Plane、Box、Sphere 等自带 UV 都在 0~1     |
| 设置了 `texture.repeat` > 1  | 会       | 采样 UV 被放大                            |
| 设置了 `texture.offset`      | 会       | 采样 UV 被平移                            |
| 手写 UV 时写了大于 1 的值    | 会       | 例如 `(2, 2)`，相当于自带平铺 2 次        |

只要超出，就由 `wrapS / wrapT` 决定显示效果。这也解释了为什么默认情况下设置 `RepeatWrapping` 看不出任何变化：UV 根本没有超出范围。

## 八、复合纹理（06）

### 1. 核心理念：一个材质可以挂多张贴图，各管一件事

`map` 只管“表面是什么颜色”。其他贴图都是**黑白图**，用灰度值去控制某一项属性在表面各处的强弱。它们**共用同一套 UV**，所以必须是同一个模型展开出来的配套贴图（06 用的就是同一套 `CityNewYork002_*` 资源）。

```js
const loader = new THREE.TextureLoader();

const texture = loader.load('/src/assets/CityNewYork002_COL_VAR1_1K.png'); // 颜色
texture.colorSpace = THREE.SRGBColorSpace;                                 // 只有颜色贴图要设

const aoMap       = loader.load('/src/assets/CityNewYork002_AO_1K.jpg');
const specularMap = loader.load('/src/assets/CityNewYork002_GLOSS_1K.jpg');

const material = new THREE.MeshBasicMaterial({
  map: texture,
  aoMap: aoMap,
  aoMapIntensity: 1,
  specularMap: specularMap,
  side: THREE.DoubleSide,
});
```

### 2. 四种贴图

| 贴图          | 灰度含义                      | 作用                                 | 配套属性                      |
| ------------- | ----------------------------- | ------------------------------------ | ----------------------------- |
| `aoMap`       | 黑 = 暗，白 = 不变            | 环境光遮蔽：缝隙、凹陷、角落变暗，增加立体感 | `aoMapIntensity`（0~1，默认 1） |
| `alphaMap`    | 黑 = 透明，白 = 不透明，灰 = 半透明 | 镂空、树叶、裂纹                     | 必须 `transparent: true`       |
| `lightMap`    | 存的是预先算好的光照结果       | 烘焙光照：静态场景不用实时算光，省性能 | `lightMapIntensity`（默认 1）  |
| `specularMap` | 白 = 反射强，黑 = 反射弱       | 控制表面各处的反光强弱               | 见下方说明                     |

### 3. 哪些材质支持（修正《各类贴图效果.html》里的表）

| 贴图          | Basic | Lambert | Phong | Standard |
| ------------- | :---: | :-----: | :---: | :------: |
| `map`         | ✓     | ✓       | ✓     | ✓        |
| `aoMap`       | ✓     | ✓       | ✓     | ✓        |
| `alphaMap`    | ✓     | ✓       | ✓     | ✓        |
| `lightMap`    | ✓     | ✓       | ✓     | ✓        |
| `specularMap` | ✓     | ✓       | ✓     | **✗**    |

html 里需要更正的几处：

- **aoMap 不只是 Standard 能用**，Basic、Lambert、Phong 都支持，06 用的就是 Basic。
- **specularMap 在 Standard 里不存在**。PBR 材质用 `roughnessMap` / `metalnessMap` 表达光泽，不用 specularMap。
- specularMap 在不同材质里的作用：
  - **Phong**：控制**高光**的强弱（配合 `shininess`）
  - **Basic / Lambert**：控制**环境反射**的强弱（配合 `reflectivity`），前提是材质设置了 `envMap`。06 没有给材质设 `envMap`，所以那里的 `specularMap` 和 `reflectivity: 0.1` 其实看不出效果
- **新版 Three.js 的 aoMap、lightMap 不再需要第二套 UV（uv2）**，直接用几何体的 `uv`。老教程里常见的 `uv2` 写法已经过时。
- 叠加方式不全是“相乘”：aoMap、alphaMap 是在原有结果上打折扣（相当于相乘），lightMap 则是**额外加上**一份光照。

### 4. 颜色空间 colorSpace

```js
texture.colorSpace = THREE.SRGBColorSpace; // 颜色贴图（map）要设
// aoMap、alphaMap、specularMap 这类数据贴图保持默认，不要设
```

- 普通图片保存的颜色是 sRGB 编码的。告诉 Three.js 这是 sRGB，它才会正确解码，否则画面会**发灰、偏亮**。
- 数据贴图里存的是“强度数值”而不是颜色，不需要转换。
- 运行时修改 `colorSpace` 后要设置 `texture.needsUpdate = true` 才会生效（06 的 GUI 里就是这么做的）。

### 5. 用 GUI 调试

06 用 `lil-gui` 把属性挂到面板上，拖动滑块实时看效果，适合对比贴图强度：

```js
import { GUI } from 'three/addons/libs/lil-gui.module.min.js';
const gui = new GUI();

gui.add(material, 'aoMapIntensity').min(0).max(1).step(0.01).name('ao贴图强度');
gui.add(texture, 'colorSpace', {
  sRGB: THREE.SRGBColorSpace,
  Linear: THREE.LinearSRGBColorSpace,
}).name('贴图颜色空间').onChange(() => {
  texture.needsUpdate = true;
});
```

## 九、环境贴图（HDR）

### 1. 加载 HDR（main(纹理贴图).js）

```js
import { RGBELoader } from 'three/addons/loaders/RGBELoader.js';

const rgbeLoader = new RGBELoader();
rgbeLoader.load('/src/assets/Alex_Hart-Nature_Lab_Bones_2k.hdr', texture => {
  texture.mapping = THREE.EquirectangularReflectionMapping;
  scene.background = texture;  // 作为 360° 背景
  scene.environment = texture; // 作为环境光照
});
```

### 2. 各行的作用

| 代码                                   | 作用                                                         |
| -------------------------------------- | ------------------------------------------------------------ |
| `RGBELoader`                           | 专门加载 `.hdr` 文件。HDR 图片比普通图片的亮度范围大得多，能记录真实的光照信息 |
| `EquirectangularReflectionMapping`     | 告诉 Three.js 这张图是**等距圆柱投影**（把 360° 球面展开成 2:1 的矩形图），要按球面环境去映射 |
| `scene.background`                     | 把 HDR 当作场景背景，四周都能看到环境                        |
| `scene.environment`                    | 把 HDR 当作环境光源，物体会被它照亮、并反射它（IBL，基于图像的光照） |

### 3. 为什么用 HDR 环境贴图

1. **真实光照**：光照信息来自真实拍摄的环境，比手动摆几个光源更自然
2. **反射**：金属、光滑材质能映出周围环境
3. **氛围**：提供 360° 背景，沉浸感强

> 注意：`scene.environment` 只对 **PBR 材质**（`MeshStandardMaterial`、`MeshPhysicalMaterial`）生效。Basic、Lambert、Phong 不会被它照亮，要反射环境得给材质单独设 `envMap`。

## 十、雾（07 + main.js）

雾让物体**离相机越远，颜色越接近雾的颜色**，用来表现空气感、景深，也能把远处的边界自然地藏起来。07 用一根 100 长的长方体，就是为了看出近处清晰、远处变淡的渐变。

```js
// 线性雾：near 之内无雾，far 之外完全被雾覆盖，中间线性过渡
scene.fog = new THREE.Fog(0x999999, 0.1, 50);

// 指数雾：只有浓度一个参数，距离越远雾越浓，增长得越来越快
scene.fog = new THREE.FogExp2(0x999999, 0.01);

// 背景色和雾色保持一致，远处物体才能“融”进背景
scene.background = new THREE.Color(0x999999);
```

| 类型      | 参数                       | 特点                           |
| --------- | -------------------------- | ------------------------------ |
| `Fog`     | 颜色, near, far            | 起止距离可控，过渡均匀         |
| `FogExp2` | 颜色, density（浓度）      | 没有起止距离，更接近真实的雾   |

> 更正：main.js 注释里把 `FogExp2` 的第二个参数写成了“开始距离、结束距离”，实际只有一个**浓度**参数，越大雾越浓，通常是 0.001 ~ 0.05 这样的小值。

要点：

- 距离指的是**物体到相机的距离**。main.js 的相机在 `(100, 100, 100)`，离原点约 173；如果用 `Fog(…, 0.1, 50)`，整个长方体都在 50 之外，会被雾完全吞掉。near、far 要按相机距离来设。
- 雾色和背景色不一致时，远处物体会变成一块和背景不同色的“剪影”。
- 雾对受光和不受光的材质都有效（材质的 `fog` 属性默认是 `true`）。

## 十二、易错点速查

| 易错说法 / 写法                              | 正确理解                                                     |
| -------------------------------------------- | ------------------------------------------------------------ |
| Three.js 会自动裁剪贴图                       | 是几何体的 UV 只覆盖了图片的一部分                           |
| 不设 RepeatWrapping，repeat 就不生效          | repeat 一直生效，只是超出部分被钳制成边缘拉伸                |
| `offset.x = 0.5` 贴图向右移                   | 贴图向**左**移，右边超出范围                                 |
| 平铺后不变形                                  | 每一份的形状由几何体宽高比决定，要让 repeat 比例匹配宽高比   |
| 设了 RepeatWrapping 就会平铺                  | UV 没超出 [0,1] 时没有效果，必须配合 repeat / offset / 大于 1 的 UV |
| `texture.onLoad = fn` 监听加载                | 无效，要用 `loader.load(url, onLoad, onProgress, onError)`   |
| 所有贴图都设 `SRGBColorSpace`                 | 只有颜色贴图（map）设，数据贴图保持默认                      |
| specularMap 在 Standard 材质里生效            | Standard 没有 specularMap，用 roughnessMap / metalnessMap    |
| aoMap / lightMap 需要 uv2                     | 新版直接用 uv，uv2 是旧写法                                  |
| `scene.environment` 能照亮所有材质            | 只对 Standard / Physical 材质生效                            |
| `FogExp2(颜色, 开始, 结束)`                   | 只有 `FogExp2(颜色, 浓度)`                                   |
| Basic 材质需要开灯                            | Basic 不受光照影响，Lambert / Phong / Standard 才需要        |

## 十三、自测题

1. 手写 UV 时把 4 个顶点的 UV 都改成 0 ~ 0.5，矩形上会显示什么？
2. 平面 `PlaneGeometry(300, 100)`，贴一张正方形图片，想平铺且不变形，`repeat` 应该怎么设？
3. `repeat.set(2, 1)`，`offset.x = 0.5`，开启 RepeatWrapping，平面最左边采样到的是图片的哪个位置？
4. 只写了 `texture.wrapS = THREE.RepeatWrapping`，其他都没改，能看到平铺吗？为什么？
5. 一张颜色贴图和一张 AO 贴图，哪张要设 `SRGBColorSpace`？
6. 用 `MeshLambertMaterial` 加载了地球贴图，场景里没有灯，会看到什么？换成 `MeshBasicMaterial` 呢？
7. 相机离物体约 200，用 `new THREE.Fog(0xffffff, 10, 100)`，物体会是什么样子？

<details>
<summary>答案</summary>

1. 显示图片的**左下 1/4**，被放大铺满整个矩形。
2. 宽高比 3:1，所以 `repeat.set(3, 1)`（或者 `6, 2` 等同比例的值）。
3. 采样 u = 0 × 2 + 0.5 = 0.5，是图片的**正中间**。
4. 看不到。repeat 还是 1，UV 没有超出 [0,1]，wrap 没有可以处理的部分。
5. 只有颜色贴图要设，AO 贴图是数据贴图，保持默认。
6. Lambert 没灯是一片黑；Basic 不受光照影响，能直接看到贴图原色。
7. 物体在 far（100）之外，会被雾完全覆盖，变成雾的颜色（白色）。

</details>
