# 02 · 解析外部模型关键帧动画

实际项目里，复杂动画（如货车沿厂区行驶、人物行走/奔跑）很少手写 `KeyframeTrack`，而是由美术在 Blender 等软件里做好后随 `.glb` / `.gltf` 一起导出。本节基于 `index.js`（上传文件 `index_6.js`）与修复后的 `mesh.js`（上传文件 `mesh_6.js`），演示如何并行加载多个外部模型并同时驱动它们自带的关键帧动画。

> **验证范围说明**：已直接读取并核验 `工厂.glb` 的 glTF JSON 头，确认其内含 **1 条动画** `Action.001_大货车`（驱动节点 `大货车` 的 `translation` / `rotation` / `scale`，时长 $40\text{s}$）；`士兵.glb` 未以可解析文本形式传入，其具体动画数量与各索引对应的动作名以浏览器运行时 `console.log` 输出为准；修复逻辑已完成静态分析与数据链路核验。

## 路线图

1. **先给 `gltf` 拆箱**：分清「Three.js 大场景 `scene`」、「加载器返回的包裹 `gltf`」和「模型本体 `gltf.scene`」，看懂 `gltf.animations` 的内部结构。
2. **逐行读懂并行加载代码**：拆解 `Promise.all`、`map`、`forEach` 和位置/缩放/旋转的简写语法。
3. **多模型共用混合器时的子树隔离**：理解为什么 `mixer.clipAction(clip, gltf.scene)` 要把当前模型 `gltf.scene` 当作第 2 参数。
4. **处理异步初始化与首帧时钟跳变**：利用 ES Module 实时绑定让主循环拿到延迟创建的 `mixer`，并在加载完成瞬间重置 `clock.getDelta()`。

## 1. 先给 `gltf` 拆箱：`gltf`、`gltf.scene`、`gltf.animations` 到底是什么？

**一句话结论**　`GLTFLoader` 返回的 `gltf` **不是** Three.js 的大场景，它只是一个普通 JS 对象（可以想象成**快递箱**）；里面的 `gltf.scene` 才是拆出来的**单个模型本体**（类型其实是 `THREE.Group`），`gltf.animations` 则是附带的**动画光盘数组**。

### 为什么它偏偏叫 `gltf.scene`，这么容易混淆？

因为在 Blender 或 glTF 2.0 文件格式标准里，**一个 `.glb` 文件内部本身就是一个独立的“小场景”**，所以 `GLTFLoader` 按规范把解析出来的模型根节点起名叫 `.scene`。请务必区分下面三个名字：

| 变量 / 属性名     | 所在位置                          | 真实类型                | 大白话理解                                           |
| ----------------- | --------------------------------- | ----------------------- | ---------------------------------------------------- |
| `scene`           | `index.js` 中 `new THREE.Scene()` | `THREE.Scene`           | **整个 3D 大舞台**（放灯光、相机、所有模型）         |
| `gltf`            | `loader.load` 回调参数            | 普通 JS 对象 `{ ... }`  | **快递箱**（不能直接 `scene.add(gltf)`，会报错！）   |
| `gltf.scene`      | `gltf` 对象内部                   | `THREE.Group`           | **箱子里拆出的单个模型本体**（如工厂模型、士兵模型） |
| `gltf.animations` | `gltf` 对象内部                   | `THREE.AnimationClip[]` | **箱子里附带的动画剪辑数组**（可以直接播）           |

### 举例看 `工厂.glb` 和 `士兵.glb` 拆箱后的真实结构

当你用 `GLTFLoader` 加载 `./工厂.glb` 成功后，拿到的 `gltf` 对象长这样：

```js
// 加载「工厂.glb」拿到的 gltf 对象（示意结构）
const factoryGltf = {
  // 1. 模型本体：一个 THREE.Group，里面装着所有建筑、地面和货车网格
  scene: Group {
    name: "Scene",
    children: [
      Mesh { name: "地面" },
      Group { name: "厂房" },
      Group { name: "大货车", position: Vector3, rotation: Euler, scale: Vector3 }, // <--- 动画驱动它
      // ... 其它模型节点
    ]
  },

  // 2. 自带动画数组：GLTFLoader 已经自动帮我们组装好了 AnimationClip 和 KeyframeTrack！
  animations: [
    AnimationClip {
      name: "Action.001_大货车", // 动画名称
      duration: 40,              // 总时长 40 秒
      tracks: [                  // 内部已经自动建好了 3 条关键帧轨道
        VectorKeyframeTrack     { name: "大货车.position",   times: [...], values: [...] },
        QuaternionKeyframeTrack { name: "大货车.quaternion", times: [...], values: [...] },
        VectorKeyframeTrack     { name: "大货车.scale",      times: [...], values: [...] },
      ]
    }
  ],

  // 3. 其它附加信息（一般较少用到）
  scenes: [ Group ],  // 文件里的所有场景列表
  cameras: [],        // 如果建模软件导出了相机，会在这里
  asset: { version: "2.0", generator: "Khronos glTF Blender I/O" }
};
```

同理，加载 `./士兵.glb` 拿到的 `gltf` 对象结构完全一样，只是里面装着士兵骨架和多个动作：

```js
// 加载「士兵.glb」拿到的 gltf 对象（典型结构示意）
const soldierGltf = {
  scene: Group {
    name: "Scene",
    children: [
      Group { name: "Character", children: [ SkinnedMesh, Bone, ... ] }
    ]
  },
  // 人物模型往往自带多条动作剪辑，靠索引 [0]、[1]、[2] 切换
  animations: [
    AnimationClip { name: "Idle"（站立）, duration: ..., tracks: [...] }, // index: 0
    AnimationClip { name: "Run"（奔跑）,  duration: ..., tracks: [...] }, // index: 1
    AnimationClip { name: "Walk"（行走）, duration: ..., tracks: [...] }, // index: 2
  ]
};
```

**坑**　把 `gltf` 当成模型直接写 `group.add(gltf)` 会直接报错（`Object3D.add: object not an instance of THREE.Object3D`），必须先拆箱取出 `gltf.scene` 再加入场景树。

## 2. 逐行拆解：`Promise.all` 并行加载多模型代码

**一句话结论**　这段代码的核心目的只有一件事：**同时发请求下载「工厂」和「士兵」，等两个都下载完之后，按配置表分别摆好位置、缩放和朝向，一起放进 `group`**。

### 先看原代码，再一行一行翻译

```js
// 并行加载配置数组里的所有模型
Promise.all(modelConfigs.map((config) => loadModel(config.url))).then((gltfs) => {
  gltfs.forEach((gltf, index) => {
    const config = modelConfigs[index];
    gltf.scene.position.set(...config.position);
    gltf.scene.scale.setScalar(config.scale);
    if (config.rotationY !== undefined) {
      gltf.scene.rotation.y = THREE.MathUtils.degToRad(config.rotationY);
    }
    group.add(gltf.scene);
  });
});
```

#### 第 1 步：`modelConfigs.map((config) => loadModel(config.url))` 干了什么？

`modelConfigs` 是你写好的配置清单（长度为 2）：

```js
modelConfigs = [
  { url: "./工厂.glb", position: [0, 0, 0],     scale: 1 },                  // 第 0 项
  { url: "./士兵.glb", position: [-30, 0, 30],  scale: 5, rotationY: 180 },  // 第 1 项
]
```

数组的 `.map()` 会遍历清单的每一项，调用 `loadModel(config.url)` 发起下载，并返回一个新数组，里面装着 **2 张“提货单”（`Promise`）**：

```js
[
  Promise(正在下载 "./工厂.glb"), // 第 0 张提货单
  Promise(正在下载 "./士兵.glb"), // 第 1 张提货单
]
```

好处是**同时发起下载**，不用傻等工厂下完才去下士兵。

#### 第 2 步：`Promise.all([...]).then((gltfs) => { ... })` 干了什么？

`Promise.all` 像一个快递驿站代收员：

- 它盯着这 2 张提货单，**等全部下载完成后**，才触发 `.then(...)`。

- 并且它会**严格保持原来的顺序**把拆好的快递箱塞进 `gltfs` 数组传给你（哪怕士兵文件小先下完，也会乖乖排在 `gltfs[1]`）：

  ```js
  gltfs = [
    factoryGltf, // gltfs[0] 一定对应 modelConfigs[0]（工厂）
    soldierGltf, // gltfs[1] 一定对应 modelConfigs[1]（士兵）
  ]
  ```

#### 第 3 步：`gltfs.forEach((gltf, index) => { ... })` 里面的每一行语法

`forEach` 会循环执行 2 次（第 1 次 `index = 0` 处理工厂，第 2 次 `index = 1` 处理士兵）：

1. **`const config = modelConfigs[index];`**
   因为顺序严格一一对应，用下标 `index` 找回当前模型对应的配置对象（`index=0` 拿到工厂配置，`index=1` 拿到士兵配置）。
2. **`gltf.scene.position.set(...config.position);`**
   `...` 是 JS 的**展开运算符**，把数组里的 3 个数“拆出来”当成 3 个独立参数传进去：
   - 对士兵来说，`config.position` 是 `[-30, 0, 30]`；
   - `set(...[-30, 0, 30])` 等价于 `set(-30, 0, 30)`。
3. **`gltf.scene.scale.setScalar(config.scale);`**
   `setScalar(5)` 是等比例缩放的简写，等价于 `gltf.scene.scale.set(5, 5, 5)`（长宽高同时放大 5 倍）。
4. **`if (config.rotationY !== undefined) { ... }`**
   工厂配置里没写 `rotationY`（值为 `undefined`），跳过不转；士兵写了 `180`，用 `THREE.MathUtils.degToRad(180)` 把角度 $180^\circ$ 转成弧度 $\pi$ 后赋给 `rotation.y`。
5. **`group.add(gltf.scene);`**
   把摆好姿势的单个模型放进公共的 `group` 里。

### 等价的“大白话展开版”（帮你彻底对齐直觉）

上面那段精简代码，展开写死成两步其实就是这样：

```js
// 如果不用 map 和 forEach，拆开来完全等价于：
const p0 = loadModel("./工厂.glb");
const p1 = loadModel("./士兵.glb");

Promise.all([p0, p1]).then(([factoryGltf, soldierGltf]) => {
  // 处理第 0 个模型：工厂
  factoryGltf.scene.position.set(0, 0, 0);
  factoryGltf.scene.scale.set(1, 1, 1);
  group.add(factoryGltf.scene);

  // 处理第 1 个模型：士兵
  soldierGltf.scene.position.set(-30, 0, 30);
  soldierGltf.scene.scale.set(5, 5, 5);
  soldierGltf.scene.rotation.y = Math.PI; // 180 度
  group.add(soldierGltf.scene);
});
```

写成 `modelConfigs` 配置数组 + `map` / `forEach` 的唯一好处是：**以后要加载 20 个模型时，只需往 `modelConfigs` 里加配置，下面加载代码一行都不用改。**

**坑**　直接写 `gltf.scene.rotation.y = 180` 会把 `180` 当成 $180$ 弧度（约 $28.65$ 圈）而不是 $180^\circ$。配置角度时务必经 `THREE.MathUtils.degToRad()` 换算；同时取动画索引时用 `Math.min(config.animation.index, gltf.animations.length - 1)` 防止越界。

## 3. 为什么 `clipAction` 第 2 参数要传 `gltf.scene`？（子树隔离）

**一句话结论**　因为 `mixer` 挂在装了**所有模型**的顶层 `group` 上；调用 `clipAction` 时把当前单个模型的 `gltf.scene` 作为第 2 参数传进去，就能把轨道的查找范围锁定在“**只在这一个模型内部找节点**”，彻底避免多模型同名节点串台。

### 看懂现在的 3 层场景树结构

```text
scene（index.js 里的 THREE.Scene 大舞台）
 └── group（mesh.js 导出的公共容器）   <--- mixer = new THREE.AnimationMixer(group)
      ├── gltfs[0].scene（工厂本体 Group）
      │    ├── 地面 / 厂房 ...
      │    └── 大货车                 <--- 工厂动画只该在这里找 "大货车"
      └── gltfs[1].scene（士兵本体 Group）
           └── Armature / 士兵网格     <--- 士兵动画只该在这里找骨骼
```

### 关键参数先看清

- `mixer.clipAction(clip, optionalRoot)`：
  - 第 1 参数 `clip`：从 `gltf.animations` 取出的动画剪辑。
  - 第 2 参数 `optionalRoot`（本例传 `gltf.scene`）：**局部查找根目录**。不传时默认从 `mixer` 绑定的顶层 `group` 往下找；传了 `gltf.scene` 后，就只在这个模型的子树里按名字找动画目标。
- `config.animation.timeScale ?? 1`：空值合并运算符（只在 `null` / `undefined` 时取默认值 `1`）。

### 正反例对比（多模型绑定与倍速默认值）

```js
// ✅ 正例：指定第 2 参数 gltf.scene 隔离各模型子树，且用 ?? 保留 timeScale: 0
const action = mixer.clipAction(gltf.animations[animIndex], gltf.scene);
action.timeScale = config.animation.timeScale ?? 1;
action.loop = config.animation.loop ? THREE.LoopRepeat : THREE.LoopOnce;
action.clampWhenFinished = !config.animation.loop;
action.play();

// ❌ 反例 1（原代码隐患）：省略第 2 参数，始终从顶层 group 查找同名节点
const action = mixer.clipAction(gltf.animations[animIndex]);
// 后果：假设你往 modelConfigs 里放了两个「士兵.glb」（士兵1 和 士兵2），
// 它们内部骨架都叫 "Armature"。省略第 2 参数后，两条动画都会从顶层 group 往下找到
// 最先出现的「士兵1」的 Armature，导致士兵1动作错乱、士兵2一动不动！

// ❌ 反例 2（原代码隐患）：用 || 设置默认倍速
action.timeScale = config.animation.timeScale || 1;
// 后果：配置 timeScale: 0 想让动画静止时，0 被判定为假值而强制改成了 1 倍速。
```

> **了解即可 · 另一种常见写法**：实际项目里也可以为每个模型各自创建一个独立的 `AnimationMixer(gltf.scene)` 放进数组 `mixers`，渲染循环中遍历 `mixers.forEach(m => m.update(delta))`。两种写法在原理上等价；共用单个 `mixer` + 传 `optionalRoot` 的好处是只需导出一个 `mixer` 即可统一控制。

## 4. 异步加载与首帧 `clock.getDelta()` 跳变

**一句话结论**　模型是异步加载的，`mixer` 在下载完成后才被创建；如果不重置 `clock`，模型就绪后的第一帧会把整个加载耗时一次性算进 `delta`，导致动画开局瞬间快进。

**最小可运行代码**（`mesh.js` 导出，`index.js` 消费）

```js
// mesh.js
const clock = new THREE.Clock();
let mixer = null;

Promise.all(...).then((gltfs) => {
  mixer = new THREE.AnimationMixer(group);
  // ... 绑定各模型 action.play() ...

  // 清空「页面启动 → 模型加载完成」期间累积的时间差
  clock.getDelta();
});

export { mixer, clock };
```

```js
// index.js
import model, { mixer, clock } from "./mesh.js";

function render() {
  if (mixer && clock) {
    const frameT = clock.getDelta();
    mixer.update(frameT);
  }
  renderer.render(scene, camera);
  requestAnimationFrame(render);
}
render();
```

**因果链**

1. 模块加载时 `mesh.js` 立即执行 `const clock = new THREE.Clock()` 开始计时，并导出 `mixer`（初始为 `null`）和 `clock`。
2. 模型下载期间（假设耗时 $2.5\text{s}$），`render()` 一直在跑，但因为 `if (mixer && clock)` 为假，期间从未调用过 `clock.getDelta()`。
3. 模型加载完成瞬间，`mixer` 被赋值为 `AnimationMixer` 实例（ES Module 的 `export { mixer }` 是**实时动态绑定**，`index.js` 下一帧就能读到新实例）。
4. 若此时不先调一次 `clock.getDelta()` 清零，下一帧 `render()` 算出的 `frameT` 就是 $2.5\text{s}$，动画会从 $0\text{s}$ 瞬间跳到 $2.5\text{s}$ 处；先调一次清零后，首帧 `frameT` 恢复正常的约 $0.0167\text{s}$。

**坑**　`index_6.js` 中创建 `PerspectiveCamera` 上方的注释误写成了 `// 正投影相机`（应为透视相机 `PerspectiveCamera`），复习时注意不要被旧注释误导。

## 速记

| 场景需求              | 核心写法                                  | 为什么需要                                            |
| --------------------- | ----------------------------------------- | ----------------------------------------------------- |
| 区分快递箱与模型本体  | `gltf.scene`（`THREE.Group`）             | `gltf` 是普通 JS 包装对象，只有 `.scene` 能加入场景树 |
| 读取外部 GLB 自带动画 | `gltf.animations[animIndex]`              | `GLTFLoader` 已自动解析为 `AnimationClip[]`           |
| 并行加载并保持顺序    | `Promise.all(configs.map(...))`           | 同时下载提速，且结果数组 `gltfs` 严格对齐配置下标     |
| 多模型防节点同名串台  | `mixer.clipAction(clip, gltf.scene)`      | 锁定轨道查找范围在当前单个模型子树内                  |
| 保留 `0` 倍速配置     | `config.animation.timeScale ?? 1`         | 避免 `0 \|\| 1` 被错误回退为 `1`                      |
| 防异步加载首帧跳帧    | 加载完成回调末尾调一次 `clock.getDelta()` | 丢弃网络下载耗时，让动画从第 $0$ 秒平滑起播           |

## 自测

1. `GLTFLoader` 回调拿到的 `gltf` 和 `gltf.scene` 分别是什么？为什么不能直接写 `group.add(gltf)`？
2. `Promise.all(modelConfigs.map((c) => loadModel(c.url)))` 同时加载工厂（大文件，3 秒下完）和士兵（小文件，0.5 秒下完），`.then((gltfs) => ...)` 中 `gltfs[0]` 拿到的是谁？
3. 当场景同时加载两份相同的 `士兵.glb` 并共用一个 `mixer = new THREE.AnimationMixer(group)` 时，为什么必须写成 `mixer.clipAction(clip, gltf.scene)`？
4. 如果模型下载耗时 3 秒，且 `mesh.js` 加载完成后没有调用 `clock.getDelta()`，第一帧动画会发生什么现象？

<details>
<summary>查看答案</summary>


1. `gltf` 是加载器返回的普通 JS 包装对象（含 `scene`、`animations`、`cameras` 等字段），不是 `THREE.Object3D`；`gltf.scene` 才是该 `.glb` 文件的模型根分组（`THREE.Group`）。直接 `group.add(gltf)` 会报类型错误。
2. 依然是**工厂**。`Promise.all` 会等所有任务完成后，严格按照传入数组 `modelConfigs` 的原始顺序返回结果，不会受谁先下完的影响。
3. 两份相同模型的内部骨骼节点名完全一致；不传第 2 参数 `gltf.scene` 时，`mixer` 会从顶层 `group` 往下找第一个同名节点，导致两份动画串台作用在第一份模型上。
4. 渲染循环在模型加载完成后首次调用 `clock.getDelta()` 会返回这 3 秒的累计耗时并传给 `mixer.update(3)`，导致动画开局瞬间向后跳进 3 秒（乘以各自的 `timeScale`）。

</details>
