# 01 · 关键帧数据与播放控制

在 Three.js 中，关键帧动画可以类比成「拍电影并播放」：先给每个属性写好时间轴剧本（`KeyframeTrack`），再把多条剧本打包成一部影片（`AnimationClip`），接着用播放器绑定到模型上（`AnimationMixer`），最后用遥控器（`AnimationAction`）和时钟（`THREE.Clock`）驱动它在渲染循环里播出来。本节基于 Three.js `0.174.0` 的 `index.html`、`index.js` 与修复后的 `mesh.js`。

## 路线图

1. **写剧本并打包影片**：用 `KeyframeTrack` 定义位置、颜色等属性随时间的变化，装进 `AnimationClip`。
2. **建播放器并接入渲染循环**：用 `AnimationMixer` 绑定目标模型，通过 `mixer.clipAction(clip)` 播放第 1 步的影片，并在 `render()` 中每帧喂入 `clock.getDelta()`。
3. **精细控制播放状态**：用 `time`、`duration`、`timeScale`、`loop`、`clampWhenFinished`、`paused`、`reset()` 以及按钮和 GUI 操控第 2 步生成的 `action`。

## 1. 写剧本并打包影片：`KeyframeTrack` 与 `AnimationClip`

**一句话结论**　用 `KeyframeTrack` 定义**单个属性**在几个关键时刻的值，再用 `AnimationClip` 把多个轨道合并成一份可复用的完整动画数据。

**关键参数先看清**

- `new THREE.KeyframeTrack(name, times, values)`：
  - `name`：目标属性路径，格式为 `"对象名.属性"` 或 `"对象名.material.属性"`（本例依赖提前给网格设置 `mesh.name = "Box"`）。
  - `times`：关键帧时间点数组（单位：秒），本例位移动画为 `[0, 2, 4, 6]`（4 个时刻），颜色动画为 `[2, 3.5, 5]`（3 个时刻）。
  - `values`：与 `times` 一一对应的扁平数值数组。每个位置 `(x, y, z)` 或颜色 `(r, g, b)` 占 $3$ 个数，因此必须严格满足：
    $$\text{values.length} = \text{times.length} \times 3$$
    颜色分量取 $0 \sim 1$ 的浮点数（如红 `(1, 0, 0)`、紫 `(0.5, 0, 0.5)`、蓝 `(0, 0, 1)`）。
- `new THREE.AnimationClip(name, duration, tracks)`：
  - `duration`：动画总时长（秒）。传 `-1` 时自动取 `tracks` 中最长轨道的结束时间。
  - `tracks`：包含多个 `KeyframeTrack` 的数组，放进去的轨道会按各自的时间轴同步播放。

**数值说明（为什么本例位置 `y` 全是 `7.5`）**

- 立方体 `BoxGeometry(15, 15, 15)` 默认几何中心在原点，高度为 $15$。
- 半高为 $15 \div 2 = 7.5$，所以初始把 `mesh.position.y += 7.5`，关键帧的 `y` 也全部填 `7.5`，保证立方体移动时底面始终贴在 $y = 0$ 的地面网格上。

**最小可运行代码**（位于 `mesh.js`）

```js
const geometry = new THREE.BoxGeometry(15, 15, 15);
const material = new THREE.MeshLambertMaterial({ color: 0xff0000 });
const mesh = new THREE.Mesh(geometry, material);
mesh.position.y += 7.5;
mesh.name = "Box"; // 必须与下方轨道名称中的 "Box" 一致
group.add(mesh);

// 4 个时刻 -> values 长度 = 4 * 3 = 12
const times = [0, 2, 4, 6];
const values = [0, 7.5, 0, 100, 7.5, 0, 0, 7.5, 100, 0, 7.5, 0];
const posKF = new THREE.KeyframeTrack("Box.position", times, values);

// 3 个时刻 -> values 长度 = 3 * 3 = 9（红 -> 紫 -> 蓝）
const colorKF = new THREE.KeyframeTrack(
  "Box.material.color",
  [2, 3.5, 5],
  [1, 0, 0, 0.5, 0, 0.5, 0, 0, 1]
);

// 打包成总时长 6 秒的动画剪辑
const clip = new THREE.AnimationClip("test", 6, [posKF, colorKF]);
```

**常见错误写法对比（✅ 正例 vs ❌ 反例）**

```js
// ✅ 正例：对象命名匹配，RGB 用 0~1，数组长度精确对齐
mesh.name = "Box";
const colorKF = new THREE.KeyframeTrack("Box.material.color", [2, 5], [1, 0, 0, 0, 0, 1]);

// ❌ 反例 1：忘了写 mesh.name = "Box"
// 结果：AnimationMixer 找不到名为 "Box" 的对象，动画静默失效不报错

// ❌ 反例 2：颜色传十六进制或 0~255（如 [255, 0, 0]）
// 结果：RGB 超出 0~1 导致颜色过曝失真，或数组长度不对导致插值错乱
```

**坑**　关键帧动画播放时会**直接覆盖**对象的原有属性值，而不是在原值基础上做增量叠加。如果 `values` 里把 `y` 写成了 `0`，即使前面写过 `mesh.position.y += 7.5`，一播放立方体还是会陷进地面一半。

## 2. 建播放器并接入渲染循环：`AnimationMixer`、`AnimationAction` 与 `Clock`

**一句话结论**　`AnimationMixer` 把动画剪辑绑定到场景对象，`action.play()` 只是按下播放键，真正让画面动起来的是渲染循环里每帧调用的 `mixer.update(delta)`。

**关键参数先看清**

- `new THREE.AnimationMixer(rootObject)`：`rootObject` 是动画查找的根节点。轨道里引用的目标对象（如 `"Box"`）既可以是 **`rootObject` 本身**（本例直接传 `mesh`），也可以是它的任意子孙节点（如传 `group`）。
- `clock.getDelta()`：返回距离上一次调用经过的秒数（帧间隔 $\Delta t$，60Hz 屏幕下约 $0.0167\text{s}$）。

**最小可运行代码**（`mesh.js` 创建并导出，`index.js` 在渲染循环中驱动）

```js
// mesh.js
const mixer = new THREE.AnimationMixer(mesh);
const action = mixer.clipAction(clip);
action.play();

const clock = new THREE.Clock();
export { mixer, clock };
export default group;
```

```js
// index.js
import model, { mixer, clock } from "./mesh.js";

function render() {
  if (mixer && clock) {
    const frameT = clock.getDelta(); // 必须传「帧间隔」
    mixer.update(frameT);            // 按时间增量推进动画并插值更新属性
  }
  renderer.render(scene, camera);
  requestAnimationFrame(render);
}
render();
```

**因果链**：`action.play()` 只把动作标记为激活状态 → 每帧 `render()` 调 `clock.getDelta()` 算出这一帧过去了多少秒 → `mixer.update(frameT)` 推进时间轴并在相邻关键帧之间做线性插值，改写 `mesh.position` 和 `mesh.material.color` → `renderer.render()` 把新状态画出来。

**正反例对比**

```js
// ✅ 正例：每帧传入时间增量 delta
mixer.update(clock.getDelta());

// ❌ 反例 1：漏写 mixer.update(...)
// 结果：即使调用了 action.play()，立方体也纹丝不动

// ❌ 反例 2：误传累计时间 clock.getElapsedTime()
// 结果：时间增量越来越大（第 10 秒一帧就推进 10 秒），动画瞬间播完或疯狂闪现
```

**坑**　只写了 `action.play()` 却忘了在 `render()` 循环里调用 `mixer.update(clock.getDelta())`，画面会完全静止；或者把 `getDelta()` 错写成 `getElapsedTime()`，导致播放速度失控。

## 3. 精细控制播放状态：时间、倍速、循环与交互

**一句话结论**　通过修改 `action`（播放进度、倍速、循环、暂停、重置）和 `clip.duration`（截断时长），可以配合按钮和 `lil-gui` 实现任意片段的播放控制。

**关键属性先看清**

- `action.loop`：循环模式，支持 `THREE.LoopRepeat`（默认无限循环）、`THREE.LoopOnce`（只播一次）、`THREE.LoopPingPong`（来回往复）。也可用 `action.setLoop(mode, repetitions)` 同时指定循环次数。
- `action.clampWhenFinished = true`：配合 `LoopOnce` 使用，播完后停在最后一帧，不弹回初始状态。
- `action.time = 3`：把当前播放指针拨到第 3 秒。**注意：`action.reset()` 会把它重新清零为 `0`。**
- `clip.duration = 5`：把影片总时长截断为 5 秒。**注意：它是 `clip` 上的属性，`action.reset()` 不会重置它。**
- `action.timeScale`：播放倍速（`2` 为 2 倍速，`0.5` 为慢放，`0` 相当于静止）。
- `action.paused`：布尔开关，`true` 暂停，`false` 恢复。

**最小可运行代码**（位于 `mesh.js`，按钮 DOM 位于 `index.html`）

```js
import { GUI } from "three/examples/jsm/libs/lil-gui.module.min.js";

action.play();
action.clampWhenFinished = true;
action.loop = THREE.LoopOnce;

// 首次加载时：从第 3 秒播放到第 5 秒后停住（此时位置在 (0,7.5,50)，颜色为蓝色）
action.time = 3;
clip.duration = 5;

// GUI 实时调倍速与查看/拖动进度
const gui = new GUI();
gui.add(action, "timeScale", 0, 10);
gui.add(action, "time", 0, clip.duration).listen();

// 按钮交互
document.getElementById("play").addEventListener("click", () => {
  action.reset().play(); // 注意：reset() 会将 action.time 归零，从 0 秒播到 5 秒
  // 若希望每次重播都从第 3 秒开始，需在 reset() 后补一行：action.time = 3;
});
document.getElementById("pause").addEventListener("click", () => {
  action.paused = true;
});
document.getElementById("resume").addEventListener("click", () => {
  action.paused = false;
});
document.getElementById("next").addEventListener("click", () => {
  action.time += 0.1; // 步进 0.1 秒（暂停状态下可逐帧观察）
});
```

**正反例对比（`reset()` 对 `time` 与 `duration` 的影响）**

```js
// ✅ 正确理解：reset() 清零 action.time，但保留 clip.duration = 5
action.reset().play();
action.time = 3; // 想继续从 3 秒起播，必须在 reset() 之后重新赋值

// ❌ 常见误区（原代码注释写反了）：以为 action.time 不会被 reset() 重置
// 结果：点「播放」后动画实际从 0 秒重新开始，而不是从 3 秒开始
```

**坑**　只设置了 `action.loop = THREE.LoopOnce` 却忘了写 `action.clampWhenFinished = true`，动画播完最后一帧的瞬间会立刻跳回第 0 秒的初始状态（颜色和位置全部弹回）。另外要注意，原示例注释里把 `action.time` 和 `clip.duration` 谁会被 `reset()` 重置写反了——记住**`reset()` 是 `action` 的方法，只重置 `action` 自己的 `time` 和 `paused` 状态，不动 `clip.duration`**。

## 了解即可 · 轨道子类与 Shader 动画的联系

- **专用轨道子类**：除了通用的 `KeyframeTrack`，Three.js 还提供了 `VectorKeyframeTrack`、`ColorKeyframeTrack`、`NumberKeyframeTrack`、`QuaternionKeyframeTrack` 等子类。旋转动画（四元数）应使用 `QuaternionKeyframeTrack` 以保证球面线性插值（Slerp）平滑不畸变。
- **与后续 Shader 动画的联系**：本节 `KeyframeTrack` 是在 CPU 上按 `clock.getDelta()` 推进时间并对关键帧做线性插值；后面写 GLSL Shader 时，你会直接把累计时间 `uTime` 作为 `uniform` 传进 GPU，用 `mix(a, b, t)` 在着色器里手写类似的插值动画。

## 速记

| 核心对象 / 属性   | 作用                       | 看哪一行                                                 |
| ----------------- | -------------------------- | -------------------------------------------------------- |
| `KeyframeTrack`   | 单条属性的关键帧剧本       | `new THREE.KeyframeTrack("Box.position", times, values)` |
| `AnimationClip`   | 合并多条轨道的影片数据     | `new THREE.AnimationClip("test", 6, [posKF, colorKF])`   |
| `AnimationMixer`  | 绑定模型并驱动插值的播放器 | `const mixer = new THREE.AnimationMixer(mesh)`           |
| `AnimationAction` | 遥控器（播/停/循环/倍速）  | `const action = mixer.clipAction(clip); action.play()`   |
| `Clock` 驱动      | 每帧传入时间间隔推进动画   | `mixer.update(clock.getDelta())`                         |
| 播完定格不回弹    | 配合 `LoopOnce` 停在末帧   | `action.clampWhenFinished = true`                        |

## 自测

1. `times = [0, 2, 4, 6]` 定义位移动画时，`values` 数组长度必须是多少？为什么？
2. `action.play()` 已经调用了，但立方体完全不动，最常见漏写了哪一步？
3. 先设置 `action.time = 3` 和 `clip.duration = 5`，点击按钮执行 `action.reset().play()` 后，动画会从第几秒播到第几秒？
4. 为什么 `mesh.js` 中给 `new THREE.AnimationMixer(mesh)` 传入 `mesh` 本身（而不是 `group`），轨道 `"Box.position"` 依然能生效？

<details>
<summary>查看答案</summary>


1. 长度必须是 `12`（$4 \times 3$）。因为每个时间点的位置包含 `x, y, z` 三个分量，`values` 必须与 `times` 一一对应。
2. 漏写了在渲染循环 `render()` 中每帧调用 `mixer.update(clock.getDelta())`。
3. 从第 `0` 秒播到第 `5` 秒。`action.reset()` 会把 `action.time` 清零，但不会修改 `clip.duration`。
4. `AnimationMixer` 按名字查找轨道目标时，会先检查传入的 `rootObject` 本身是否同名（本例 `mesh.name = "Box"`），匹配则直接绑定，不强制要求只能是子级。

</details>
