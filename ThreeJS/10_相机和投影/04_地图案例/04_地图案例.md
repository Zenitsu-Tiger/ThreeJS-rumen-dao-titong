# 04 地图案例

> 本章两个案例：
> - **地图案例**：用河南省边界的经纬度画出一个平面地图，用正投影相机 + 包围盒让地图刚好铺满屏幕。文件：`mesh.js`、`index.js`、`data.js`
> - **圆周运动案例**：加载一个工厂模型，让透视相机绕着它转圈。文件：`mesh.js`、`index.js`

---

# 一、地图案例

## 1. 用经纬度画出地图轮廓

**一句话结论**：把边界上每个点的经纬度直接当成 (x, y) 坐标，连成一个封闭轮廓 `Shape`，再用 `ShapeGeometry` 把轮廓内部填满，就得到一块平面地图。

**数据长什么样**（data.js）：一个数组，每一项是 `[经度, 纬度]`，例如 `[110.3906, 34.585]`。共 63 个点，首尾是同一个点，围成闭合的边界。

**代入数字**：第一个点 `[110.3906, 34.585]` → x = 110.3906，y = 34.585，z = 0。也就是说，场景里 **1 个单位 = 1 度经纬度**，整个地图画在 xy 平面上，正对着 z 轴。

**最小代码**（mesh.js）

```js
import * as THREE from "three";
import data from "./data.js";

const group = new THREE.Group();

// 经纬度 → 二维向量
const pointsArr = [];
data.forEach((e) => {
  pointsArr.push(new THREE.Vector2(e[0], e[1])); // x = 经度，y = 纬度
});

// Shape：一个平面多边形轮廓
const shape = new THREE.Shape(pointsArr);
// ShapeGeometry：把轮廓内部填满，生成平面几何体
const geometry = new THREE.ShapeGeometry(shape);

const material = new THREE.MeshLambertMaterial({
  color: 0x00ffff,
  side: THREE.DoubleSide, // 正反两面都显示
});
const mesh = new THREE.Mesh(geometry, material);
group.add(mesh);

export default group;
```

**坑**

- 平面默认只有正面可见，从背面看是透明的。加 `side: THREE.DoubleSide` 后，相机转到背面也能看到。
- 经纬度直接当坐标只适合小范围的演示。地球是球面，范围大了形状会有变形，这里不展开。

---

## 2. 用包围盒算出地图的尺寸和中心

**一句话结论**：地图的位置（x 约 113、y 约 33）离原点很远，大小也只有几个单位，所以要先用包围盒算出**中心**和**尺寸**，后面相机才知道往哪看、看多大。

**代入数字**（实际运行结果）

| | x（经度） | y（纬度） |
|---|---|---|
| 最小值 min | 110.3906 | 31.4209 |
| 最大值 max | 116.6309 | 36.3428 |
| 尺寸 size = max - min | **6.2403** | **4.9219** |
| 中心 center = (min + max) / 2 | **113.5107** | **33.8819** |

z 方向全是 0，因为地图是一块平面。

**最小代码**

```js
const box3 = new THREE.Box3();
box3.setFromObject(mesh);

const size = new THREE.Vector3();
box3.getSize(size);      // (6.2403, 4.9219, 0)

const center = new THREE.Vector3();
box3.getCenter(center);  // (113.5107, 33.8819, 0)
```

**坑**

- 原代码的尺寸变量叫 `scale`，容易和 `mesh.scale` 搞混，这里改成 `size`。
- index.js 里写死的 `x = 113.51`、`y = 33.88` 就是从这里打印出来的中心点。数据一换就要重新抄一遍，更好的做法是直接把 `center` 导出给 index.js 使用。

---

## 3. 相机对准地图中心

**一句话结论**：正投影相机能看到的盒子是**以相机自己为中心**的，所以相机必须放到地图中心的正前方，地图才会出现在画面正中。

**代入数字**：相机盒子 s = 2.5，只能看到相机周围上下各 2.5 的范围

- 相机放在原点正前方 (0, 0, 300)：地图中心在 x = 113.5，离相机 113.5 远，远远超出盒子的范围 → **画面里什么都没有**
- 相机放在 (113.51, 33.88, 300)：地图中心正好在相机正前方 → 地图在画面正中 ✅

z = 300 只是"站在地图前面多远"，正投影下远近不影响大小，只要在 near(1) ~ far(8000) 之间就行。

**最小代码**（index.js）

```js
const x = 113.51; // 包围盒中心
const y = 33.88;

camera.position.set(x, y, 300); // 先放位置：站在地图中心正前方
camera.lookAt(x, y, 0);         // 再定朝向：看向地图中心

const controls = new OrbitControls(camera, renderer.domElement);
controls.target.set(x, y, 0);   // 控制器的观察点也设为地图中心
controls.update();

axesHelper.position.set(x, y, 0); // 坐标轴辅助线也挪到地图中心，方便观察
```

**另一种思路**：不挪相机，而是用上一章的方法把地图挪回原点：`mesh.position.sub(center)`。之后相机、控制器都对准 (0, 0, 0) 就行，不用到处写 113.51。

**坑**

- **原代码先写 `lookAt` 再写 `position.set`，顺序反了。** `lookAt` 是"站在当前位置朝目标转身"，执行时相机还在默认位置 (0,0,0)，算出来的朝向是斜着指向 (113.51, 33.88, 0)，再把相机挪走，朝向也不会跟着改。实测这样设置后相机朝向是 (0.96, 0.29, 0)，几乎是横着看，地图根本不在画面里。原代码能正常显示，只是因为后面创建 OrbitControls 时，控制器按 target 重新对准了一次。**正确顺序是先 `position`，后 `lookAt`。**

---

## 4. 为什么 s 要贴合包围盒尺寸

**一句话结论**：s 决定相机能看到多大的范围（高 2s，宽 2s·k），让这个范围刚好比地图大一点，地图就能完整显示，并且尽量铺满屏幕。

**代入数字**：地图宽 6.24、高 4.92，s = 2.5

- 相机可视高度 = 2 × 2.5 = **5** ≥ 4.92 ✅，上下刚好装下
- 相机可视宽度 = 5 × k，要装下 6.24，需要 k ≥ 6.24 / 5 ≈ **1.25**
  - 常见的 16:9 宽屏，k ≈ 1.78，宽度 8.9 ✅
  - 窗口拉成正方形，k = 1，宽度只有 5 ❌，地图左右各被切掉约 0.62

| s | 可视高度 | 效果 |
|---|---|---|
| 5（原文写的值） | 10 | 地图只占画面高度的一半左右，周围大片空白 |
| 2.5（代码里的值） | 5 | 上下刚好装下，几乎铺满 |
| 1.5 | 3 | 太小，地图上下都被切掉 |

**最小代码**：上下、左右都要装下，取两者中较大的那个

```js
const k = width / height;
const sForHeight = size.y / 2;        // 装下高度：4.92 / 2 = 2.46
const sForWidth = size.x / 2 / k;     // 装下宽度：6.24 / 2 / k
const s = Math.max(sForHeight, sForWidth) * 1.05; // 留 5% 边距
const camera = new THREE.OrthographicCamera(-s * k, s * k, s, -s, 1, 8000);
```

- 16:9 屏：sForHeight = 2.46，sForWidth = 1.75 → 取 2.46，乘 1.05 后约 2.58
- 正方形窗口：sForHeight = 2.46，sForWidth = 3.12 → 取 3.12，乘 1.05 后约 3.28

**坑**

- 原文说"2s 约等于模型高度 scale.y 即可"，只考虑了上下。窗口偏窄时，左右会先装不下。
- 原文正文写的是 `s = 5`，代码里是 `s = 2.5`，以代码为准。

# 二、圆周运动案例

## 5. 相机沿圆周运动

**一句话结论**：每一帧让角度 angle 增加一点，用 `x = R·cos(angle)`、`z = R·sin(angle)` 算出圆上的新位置，相机就在水平面上绕着原点转圈。

**代入数字**：半径 R = 100

| angle（弧度） | x = 100·cos | z = 100·sin | 位置 |
|---|---|---|---|
| 0 | 100 | 0 | 正右方 |
| π/2 ≈ 1.57 | 0 | 100 | 正前方 |
| π ≈ 3.14 | -100 | 0 | 正左方 |
| 3π/2 ≈ 4.71 | 0 | -100 | 正后方 |

- angle 每帧加 0.01，转一整圈（2π ≈ 6.28）需要 628 帧，60 帧/秒的屏幕上约 **10.5 秒**一圈
- y 没有被修改，一直是初始设置的 123，所以相机是在 **y = 123 高度的水平圆**上转

```
        z
        │   ● angle = π/2 (0, 100)
        │
(-100,0)●───┼───● angle = 0 (100, 0)
        │   原点
        │   ● angle = 3π/2 (0, -100)
   （从上往下看，相机沿这个圆转）
```

**最小代码**（index.js）

```js
const camera = new THREE.PerspectiveCamera(45, width / height, 1, 8000);
camera.position.set(202, 123, 125); // 只有 y=123 会保留，x、z 第一帧就被覆盖
camera.lookAt(0, 0, 0);

let angle = 0;  // 起始角度（弧度）
const R = 100;  // 圆周半径

function render() {
  angle += 0.01;
  camera.position.x = R * Math.cos(angle);
  camera.position.z = R * Math.sin(angle);
  camera.lookAt(0, 0, 0); // 每帧重新对准原点，见第 6 节
  renderer.render(scene, camera);
  requestAnimationFrame(render);
}
render();
```

**坑**

- 初始位置 (202, 123, 125) 里的 x、z 第一帧就被圆周公式覆盖了，相机会立刻"跳"到半径 100 的圆上。想让开场没有跳动，初始位置应该写成 `(R, 123, 0)`。
- 原代码注释写的是"正投影相机"，实际用的是透视相机 `PerspectiveCamera`，这里已改正。
- 转速和屏幕刷新率有关：120Hz 的屏幕一秒执行 120 帧，转速是 60Hz 屏幕的两倍。
- 模型是异步加载的：`loader.load` 下载完 glb 文件才会执行回调，把模型加进 group。所以页面刚打开时 group 是空的，模型会晚一点才出现。

---

## 6. 为什么每帧都要重新 lookAt

**一句话结论**：改 `position` 只是把相机搬到新位置，朝向不会自动跟着变。要让镜头一直对着原点，每次搬完都得重新 `lookAt` 一次。

**代入数字**：相机从 angle = 0 处的 (100, 123, 0) 出发，一开始对准原点，视线朝向原点方向

- 不加 lookAt，转了四分之一圈到 (0, 123, 100)：视线还是保持最初的方向（朝着 -x 斜下方），而原点现在在相机的 -z 方向 → 模型从画面一侧滑出去
- 加上 lookAt：每一帧都重新朝向原点，模型始终在画面正中

可以这样理解：`position` 决定"站在哪"，`lookAt` 决定"看哪里"，两者互不影响。人绕着桌子走一圈，如果脖子一直不转，桌子就会从眼前滑过；只有边走边转头盯着桌子，桌子才会一直在视线中间。

**坑**

- **这个案例里同时创建了 OrbitControls，两者会冲突。** 渲染循环每帧都会改写相机的 x、z 和朝向，鼠标拖动改变的 x、z 下一帧就被覆盖；只有 y（高度）没人改写，会被保留下来，结果就是"左右拖不动、上下拖得动"，表现很奇怪。自动绕圈和鼠标控制选一个就行，用自动绕圈时把 OrbitControls 的相关代码删掉。

# 📋 速记表

| 知识点 | 记住这句 | 代码 / 数字 |
|---|---|---|
| 经纬度画地图 | 经度当 x、纬度当 y，1 单位 = 1 度 | `new THREE.Vector2(lng, lat)` |
| Shape | 平面多边形轮廓 | `new THREE.Shape(pointsArr)` |
| ShapeGeometry | 把轮廓内部填满成平面 | `new THREE.ShapeGeometry(shape)` |
| 双面显示 | 平面背面默认看不见 | `side: THREE.DoubleSide` |
| 地图包围盒 | 尺寸 6.24 × 4.92，中心 (113.51, 33.88) | `box3.getSize / getCenter` |
| 相机对准中心 | 正投影盒子以相机为中心，相机要站到地图正前方 | `position.set(x, y, 300)` |
| 设置顺序 | 先 position 再 lookAt，反了朝向会错 | `position.set → lookAt` |
| 居中另一法 | 把地图挪回原点，相机对准原点 | `mesh.position.sub(center)` |
| s 怎么取 | 上下、左右都要装下，取较大值 | `s = max(h/2, w/2/k)` |
| s 太大 / 太小 | 太大四周留白，太小被切掉 | s=5 留白，s=2.5 刚好 |
| 圆周公式 | x = R·cos，z = R·sin，y 不变 | R=100，每帧 +0.01 弧度 |
| 一圈多久 | 2π ÷ 0.01 = 628 帧 ≈ 60Hz 下 10.5 秒 | 刷新率越高转得越快 |
| 每帧 lookAt | 搬位置不会自动转头 | `camera.lookAt(0, 0, 0)` |
| 和控制器冲突 | 自动绕圈会覆盖鼠标操作，二选一 | 删掉 OrbitControls |
| 异步加载 | 模型下载完才加进 group，会晚出现 | `loader.load(url, callback)` |
