# 地图案例

## 为什么s的值要尽量贴合mesh模型的包围盒尺寸？

简单来说：s 定义了正交相机能看到的、现实世界中的一个矩形区域的高度，而模型的包围盒尺寸是模型在现实世界中的实际大小。要想让模型正好填满相机的视野（也就是屏幕），那么相机能看到的区域大小就必须和模型的大小相匹配。

我们来拆解一下：

### 1. s 的作用是什么？

在你的 index.js 代码中：

```js
// 控制left right top bottom near far范围大小
const s = 5;
const camera = new THREE.OrthographicCamera(-s * k, s * k, s, -s, 1, 8000);
```

正交相机和我们人眼看到的透视相机不同，它没有“近大远小”的效果。你可以把它想象成一个上帝视角的“框”，这个框有多大，就能看到多大的东西。

- top: s 和 bottom: -s 定义了这个“框”的顶部和底部位置。所以，这个框的总高度是 s - (-s) = 2s。在你的代码里，总高度就是 10 个单位。

- left: -s * k 和 right: s * k 定义了“框”的左右边界。宽度是根据高度和屏幕的宽高比 k 自动计算的，以保证画面不会被拉伸。

所以，变量 s 直接控制了相机视野的高度。s 越大，相机能看到的区域就越大，场景中的物体就会显得越小。s 越小，相机能看到的区域就越小，物体就会显得越大（就像被放大了）。

### 2. 包围盒 (Bounding Box) 尺寸是什么？

在你的 mesh.js 中：

```js
const box3 = new THREE.Box3();
box3.expandByObject(mesh); // 计算mesh的包围盒
const scale = new THREE.Vector3();
box3.getSize(scale); // 获取包围盒的尺寸（长、宽、高）
```

box3.getSize() 计算出了你的地图模型在 3D 空间中实际占据的 宽度、高度 和 深度。这个尺寸是模型本身的固有属性。

### 3. 为什么两者需要匹配？

现在我们把两者结合起来：

- 你有一个固定大小的模型（由包围盒尺寸决定）。

- 你有一个可变大小的取景框（由 s 决定）。

你的目标是：让模型正好填满这个取景框。

- 如果 s 设置得太大：取景框会比模型大很多。结果就是，模型在屏幕上看起来很小，周围有大片的空白。

- 如果 s 设置得太小：取景框会比模型小。结果就是，你只能看到模型的一部分，超出的部分会被裁剪掉，看不见。

- 只有当 s 的值恰到好处 (即 2 * s 约等于模型的高度 scale.y），取景框的大小才会和模型的大小基本一致。这样，模型就能最大程度地、完整地显示在屏幕上，实现“占满屏幕”的效果。

所以，在 OrthographicCamera 的场景中，我们通常会先计算出要展示的核心物体的包围盒大小，然后根据这个大小来设置 s，从而达到最佳的展示效果。



# 圆周运动案例

### 1. 相机如何实现圆周运动？

这部分是利用了基础的三角函数知识。想象一个以原点 (0,0) 为中心的圆，在一个二维平面上，圆上任意一点的坐标 (x, z) 可以通过半径 R 和角度 angle 来表示：

- x = R * cos(angle)

- z = R * sin(angle)

在你的 index.js 代码中：

```js
// 圆周运动的角度起始值
let angle = 0;
// 相机圆周运动的半径
const R = 100;

function render() {
  angle += 0.01; // 在每一帧都增加一点角度
  // 根据新的角度和固定的半径，计算出相机在X和Z轴上的新位置
  camera.position.x = R * Math.cos(angle);
  camera.position.z = R * Math.sin(angle);
  // ...
  renderer.render(scene, camera);
  requestAnimationFrame(render);
}
```

1. angle += 0.01;：在 render 函数的每一次调用（也就是每一帧）中，我们都让角度 angle 增加一个微小的值。

1. camera.position.x = R * Math.cos(angle)

1. camera.position.z = R * Math.sin(angle)

这两行代码就是根据新的角度，使用三角函数计算出相机在 X-Z 平面（可以理解为“地面”）上的新坐标。相机的 y 坐标没有改变，所以它是在一个水平面上绕着 Y 轴做圆周运动。

随着 angle 的不断增大，相机的位置点 (x, z) 就在一个半径为 R 的圆周上移动，从而实现了环绕观察的效果。

### 2. 为什么必须在 render 中重新执行 camera.lookAt(0,0,0)？

这是最关键的一点。在 Three.js 中，改变一个对象的位置（position）和改变它的朝向（rotation）是两个独立的操作。

你可以把相机想象成一个人：

- camera.position.set(...) 就像是你移动到了一个新的位置。

- camera.lookAt(...) 就像是你转动头部，让你的视线朝向某个目标。

在你的 render 循环中：

1. 你只更新了 camera.position，这相当于你只是把相机平移到了圆周上的一个新点。

1. 如果你不告诉相机接下来要看哪里，它会保持它之前的朝向。

不加 lookAt 的后果：

想象一下，相机初始时朝向原点 (0,0,0)。当它沿着圆周移动时，如果它的朝向不变，它就会一直看着同一个方向。

**从屏幕上看，场景中的物体（比如你的工厂模型）会从画面的一侧“平移”到另一侧，而不是始终保持在画面中心。这就像是你坐在一列环形小火车上，但你始终面朝北方，你看到的风景就会不断从你眼前划过，而不是感觉火车在围绕风景旋转。**

加上 lookAt 的作用：

通过在更新完 position 之后，立刻执行 camera.lookAt(0, 0, 0)，你是在每一帧都强制命令相机：“移动到新位置后，请立刻把你的‘头’转向场景的原点！”

这样一来，无论相机运动到圆周上的哪个位置，它的镜头都始终对准中心点 (0,0,0)，从而实现了真正的、围绕物体旋转的观察效果。
