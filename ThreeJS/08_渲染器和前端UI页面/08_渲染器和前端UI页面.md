# 08 渲染器和前端 UI 页面

> 复习方式：每节先看「一句话结论」，能回忆起来就跳过；想不起来再看代码和「坑」。

本章的主线：Three.js 的画布（canvas）本质上就是页面里一个普通的 DOM 元素，可以和按钮、进度条这些 HTML UI 组合在一起，做成完整的网页应用。

---

## 1. importmap：不用打包工具也能 import three

**一句话结论**：在 HTML 里写一个 `<script type="importmap">`，把 `'three'` 这样的模块名映射到 CDN 地址。之后在普通的 `.html` + `.js` 里，也能像在 Vite 项目中一样写 `import * as THREE from 'three'`。

```html
<script type="importmap">
  {
    "imports": {
      "three": "https://esm.sh/three@0.174.0/build/three.module.js",
      "three/examples/jsm/": "https://esm.sh/three@0.174.0/examples/jsm/"
    }
  }
</script>

<!-- 业务代码必须是 type="module" 才能用 import -->
<script src="./index.js" type="module"></script>
```

```js
// index.js：和 Vite 项目里的写法完全一样
import * as THREE from 'three'
import { OrbitControls } from 'three/examples/jsm/controls/OrbitControls.js'
```

| 映射写法 | 含义 |
|---|---|
| `"three": ".../three.module.js"` | 精确匹配：`import ... from 'three'` |
| `"three/examples/jsm/": ".../examples/jsm/"` | 前缀匹配（以 `/` 结尾）：凡是以这段开头的路径，都把前缀替换掉 |

**适用场景**：写小 demo、示例页面，不想搭建 Vite 工程的时候。

**坑**
- `importmap` 必须写在使用 `import` 的 `<script type="module">` **之前**。
- 业务脚本漏写 `type="module"`，`import` 语句会直接报语法错误。
- 直接双击打开 `.html`（`file://` 协议）通常加载不了模块和模型，要用本地服务器打开（比如 VS Code 的 Live Server）。

## 2. WebGLRenderer 的常用配置

**一句话结论**：渲染器的配置分两类：一类在 `new` 的时候作为参数传入，**之后不能再改**；另一类通过方法随时设置。

```js
const renderer = new THREE.WebGLRenderer({
  antialias: true,              // 抗锯齿：模型边缘更平滑
  preserveDrawingBuffer: true,  // 保留画布内容：截图下载需要它（第 3 节）
})

renderer.setPixelRatio(window.devicePixelRatio)  // 适配高清屏，防止画面模糊
renderer.setSize(width, height)                  // 画布尺寸
renderer.setClearColor(0x444444)                 // 画布背景色

document.body.appendChild(renderer.domElement)   // domElement 就是那个 canvas
```

| 配置 | 方式 | 作用 |
|---|---|---|
| `antialias` | 构造参数 | 抗锯齿，模型边缘不再是锯齿状 |
| `preserveDrawingBuffer` | 构造参数 | 渲染后保留画布内容，可以读取成图片 |
| `setPixelRatio()` | 方法 | 按屏幕像素密度渲染，Retina 屏上不模糊 |
| `setSize()` | 方法 | 设置 canvas 的宽高 |
| `setClearColor()` | 方法 | 设置画布背景色（没有物体的区域显示的颜色） |

### 为什么要 setPixelRatio

高清屏的 `devicePixelRatio` 通常是 2 或 3，也就是 1 个 CSS 像素对应 2×2 或 3×3 个物理像素。不设置的话，canvas 按 CSS 尺寸渲染，再被拉伸到物理像素上，画面就会发虚。

**坑**
- `antialias` 和 `preserveDrawingBuffer` 只能在构造时传入，之后写 `renderer.antialias = true` 没有效果。
- `setPixelRatio` 越大，需要渲染的像素越多，开销也越大。像素比是 3 时，渲染量是 1 时的 9 倍。

## 3. 把画布内容下载成图片

**一句话结论**：`renderer.domElement` 就是一个 canvas，用 `canvas.toDataURL()` 把画面转成图片数据，再用一个临时的 `<a download>` 触发下载。前提是渲染器开启了 `preserveDrawingBuffer: true`。

```js
document.getElementById('download').addEventListener('click', () => {
  const link = document.createElement('a')
  link.href = renderer.domElement.toDataURL('image/png')  // canvas → base64 图片
  link.download = 'canvas.png'                            // 下载时的文件名
  link.click()                                            // 模拟点击，触发下载
  link.remove()
})
```

### 为什么需要 preserveDrawingBuffer

```text
默认（false）：渲染一帧 → 显示到屏幕 → 画布缓冲区被清空
               点击下载时去读取 → 读到空白 / 全黑图片 ❌

开启（true）：  渲染一帧 → 显示到屏幕 → 画布内容保留
               点击下载时去读取 → 读到当前画面 ✅
```

**坑**
- 下载的图片全黑或全透明：几乎都是没开 `preserveDrawingBuffer`。
- 开启后有一定的性能损耗，只在需要截图功能时开启。

## 4. 模型加载进度条

**一句话结论**：`loader.load` 的**第三个参数**是加载进度回调，用 `xhr.loaded / xhr.total` 算出百分比，再去更新进度条 DOM；加载完成后，在第二个参数（成功回调）里隐藏进度条。

### load 的四个参数

```js
loader.load(
  url,           // 1. 模型地址
  onLoad,        // 2. 加载成功（第 6 章一直在用）
  onProgress,    // 3. 加载进度（本章新增）
  onError        // 4. 加载失败（可选）
)
```

### 进度条实现

HTML 结构：外层是固定宽度（400px）的容器，内层的宽度随进度从 0 增长到 400px。

```html
<div id="container">      <!-- 外框：宽 400px，overflow: hidden -->
  <div id="per"></div>    <!-- 进度：宽 0 → 400px -->
</div>
```

```js
loader.load(
  './public/工厂.glb',
  gltf => {
    model.add(gltf.scene)
    document.getElementById('container').style.display = 'none'  // 加载完成，隐藏进度条
  },
  xhr => {
    const percent = xhr.loaded / xhr.total            // 0 ~ 1
    const per = document.getElementById('per')
    per.style.width = percent * 400 + 'px'            // 进度条长度
    per.style.textIndent = percent * 400 + 5 + 'px'   // 文字跟在进度条右边
    per.innerHTML = Math.floor(percent * 100) + '%'   // 百分比文字
  }
)
```

| 属性 | 含义 |
|---|---|
| `xhr.loaded` | 已经下载的字节数 |
| `xhr.total` | 文件总字节数 |

**坑**
- `xhr.total` 依赖服务器返回文件大小（`Content-Length` 响应头）。有些服务器开启 gzip 压缩后不返回这个值，`total` 会是 0，算出来的百分比就是 `Infinity` 或 `NaN`。
- 没写 `onError` 时，加载失败（比如路径写错）进度条会一直停在原处，用户看不出出了什么问题。正式项目建议加上失败提示。

## 5. 画布和 HTML UI 的布局

**一句话结论**：canvas 和普通 DOM 一样参与页面布局。UI（顶部栏、按钮、进度条）用 `position: absolute` 浮在画布上面；画布尺寸要和 UI 布局对应，并且 `resize` 时要**用同样的规则**重新计算。

```html
<!-- 顶部栏：绝对定位，浮在 canvas 上方 -->
<div style="position: absolute; top: 0; left: 0; right: 0; height: 55px;">
  <button id="download">下载</button>
</div>
```

### 两种布局思路

| 思路 | 画布尺寸 | 适用 |
|---|---|---|
| UI **浮在**画布上（本章代码） | 整个窗口 `innerWidth × innerHeight` | 工具栏、按钮较少，可以遮住一部分画面 |
| UI **占位**，画布让出空间 | 窗口减去 UI 尺寸，如 `innerWidth - 200` | 有固定的侧边栏、顶栏，不能遮挡画面 |

### resize 要和初始化用同一套计算

```js
// 把尺寸计算抽成一个函数，初始化和 resize 共用，避免两处写得不一致
function getSize() {
  return { width: window.innerWidth, height: window.innerHeight }
}

window.addEventListener('resize', () => {
  const { width, height } = getSize()
  renderer.setSize(width, height)
  camera.aspect = width / height
  camera.updateProjectionMatrix()   // 改了 aspect 必须调用，否则画面会拉伸
})
```

**坑**
- 本章 `index.js` 里有一处不一致：初始化用的是整个窗口尺寸，`onresize` 里却减去了 200 和 60（这是侧边栏布局时的写法）。结果是一旦缩放窗口，画布就会变小，右边和下边露出空白。两处要统一。
- 同一个文件里的注释把宽和高写反了（`width` 的注释写成了"画布高度"）。

## 6. 一页速记

| 需求 / 现象 | 解法 |
|---|---|
| 不用 Vite，在 html 里 import three | `<script type="importmap">` + `type="module"` |
| 模型边缘有锯齿 | `new WebGLRenderer({ antialias: true })` |
| 高清屏上画面模糊 | `renderer.setPixelRatio(window.devicePixelRatio)` |
| 修改画布背景色 | `renderer.setClearColor(0x444444)` |
| 截图下载 | `canvas.toDataURL()` + `<a download>` |
| 下载的图片是黑的 | `new WebGLRenderer({ preserveDrawingBuffer: true })` |
| 显示加载进度 | `loader.load` 的第 3 个参数，`xhr.loaded / xhr.total` |
| 加载完隐藏进度条 | 在第 2 个参数（成功回调）里 `display = 'none'` |
| 按钮浮在画布上 | `position: absolute` |
| 窗口缩放后画布尺寸不对 | 初始化和 resize 用同一套尺寸计算 + `updateProjectionMatrix()` |
