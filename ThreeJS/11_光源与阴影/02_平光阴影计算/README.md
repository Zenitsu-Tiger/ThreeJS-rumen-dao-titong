# 平行光阴影计算

在Three.js中，阴影的实现主要依赖一种名为 **阴影贴图 (Shadow Mapping)** 的技术。这个过程可以分为两个核心步骤：

#### 第一步：深度图渲染 (从光源视角)

1. Three.js会暂时将摄像机移动到光源的位置。

1. 从光源的"视点"出发，渲染一次场景。但这次渲染并非为了生成彩色图像，而是为了生成一张深度图 (Depth Map)，也就是阴影贴图。

1. 这张深度图记录了从光源到场景中每个物体表面的最近距离。离光源近的物体在这张图上颜色较浅，远的则较深。

#### 第二步：最终场景渲染 (从主摄像机视角)

1. 摄像机回到其原始位置，开始正常渲染我们最终看到的场景。

1. 在为每个像素着色时，渲染器会进行一次计算：**它会判断当前像素在世界空间中的位置，如果这个位置被光源照射到，渲染器会查询第一步生成的深度图。**

1. 通过比较“当前像素到光源的距离”和“深度图中记录的相同方向上的最近距离”，渲染器就能判断出这个像素是否处于阴影之中。

   - 如果两个距离相等，说明该像素是离光源最近的点，它被照亮。

   - 如果当前像素的距离 **大于** 深度图中记录的距离，说明在它和光源之间有其他物体遮挡，因此它处于阴影中。

### 常见问题解答

现在，让我们来回答你提出的具体问题：

#### 1. shadow.camera 的属性为什么决定了阴影的渲染范围？

shadow.camera 就是在 阴影渲染第一步 中，那个被临时放置在光源位置的虚拟摄像机。

这个摄像机有一个 视锥体 (View Frustum)，它定义了摄像机能够"看到"的区域范围。对于平行光（DirectionalLight）来说，它的 shadow.camera 是一个正投影相机（OrthographicCamera），其视锥体是一个长方体，由 left, right, top, bottom, near, far 这六个属性共同定义。

**核心原因在于：只有位于这个视锥体内部的物体，才会被渲染到深度图中，从而才具备投射阴影的能力。**

- 范围太小：如果一个物体的 castShadow 设置为 true，但它的一部分或全部位于 shadow.camera 的视锥体之外，那么它超出的部分将不会被渲染到深度图，其阴影也就会被奇怪地"裁剪"掉。

- 范围太大：如果将视锥体设置得过大，远超场景内物体的范围，深度图有限的像素（分辨率，如 shadow.mapSize）就需要覆盖更广阔的空间。这会导致分配给每个物体的像素变少，使得阴影边缘产生严重的锯齿和模糊，降低阴影质量。

因此，精确地设置 shadow.camera 的范围，使其刚刚好包裹住所有需要投射阴影的物体，是生成高质量、正确阴影的关键。

#### 2. 为什么平行光的阴影事实上由正投影相机产生？

这完全是由平行光的物理特性决定的。

- 平行光 (DirectionalLight) 被设计用来模拟像太阳光一样距离无限远的光源。它的特点是所有光线都是 相互平行 的。

- 正投影相机 (OrthographicCamera) 的特点是它在渲染时 没有透视效果。无论物体距离相机多远，它在最终图像上的大小都是一样的。它的投影线也是相互平行的。

这两者的特性完美匹配。

当 Three.js 为平行光生成深度图时，它需要捕捉到一个"所有光线平行照射下"的场景深度快照。使用正投影相机来完成这个任务是最符合物理逻辑的。它能确保所有物体都沿着与光线平行的方向被"拍"进深度图，没有任何透视变形。

相比之下，像聚光源（SpotLight）或点光源（PointLight）是从一个点向外发散光线，这具有明显的透视关系。因此，它们的 shadow.camera 就是一个 透视相机 (PerspectiveCamera)。



# 简易版理解

### Three.js 阴影渲染的“幻灯机”故事

想象一下，Three.js 要在一个物体（比如地面）上画出另一个物体（比如立方体）的影子，它会这样做：

第一步：跑到灯泡的位置，拍一张“距离照片”

1. Three.js 会偷偷地把你的主摄像机“瞬移”到光源（比如那个平行光）的位置。

1. 它从光源的视角，拍一张特殊的黑白照片。这张照片不记录颜色，只记录 “我（光源）离各个物体有多远”。

- 离得近的物体，在照片上是深色的。

- 离得远的物体，在照片上是浅色的。

1. 这张特殊的“距离照片”，就是我们接下来要用的“幻灯片”。在技术上，它叫 阴影贴图 (Shadow Map)。

第二步：用这张“距离照片”当幻灯片，往场景里投影

1. 拍完照后，摄像机瞬间回到原来的位置，准备渲染我们最终看到的画面。

1. 同时，那个光源就像一个幻灯机，把刚刚拍好的“距离照片”这张幻灯片，朝着原来的方向投影到整个场景上。

第三步：判断谁在影子里

现在，当渲染器开始给地面上的某一个点上色时，它会问自己两个问题：

1. “我这个地面点，离光源有多远？”

1. “幻灯片投射到我这个位置时，上面记录的‘标准距离’是多远？”

如果 “我的距离” > “幻灯片上的标准距离”，那就意味着，在我 和 光源之间，肯定有另一个东西（比如那个立方体）挡着！所以，我这个点应该被涂成黑色，也就是在影子里。

如果两个距离一样，说明没东西挡着，那就正常被光照亮。

------

现在，用这个“幻灯机”的比喻，再来回答你的两个问题就简单多了：

#### 1. shadow.camera 的属性为什么决定了阴影的渲染范围？

shadow.camera 就是 第一步里那台用来拍“距离照片”的特殊照相机。

left, right, top, bottom 这些属性，就相当于你给这台特殊照相机设置的 取景框。你在告诉它：“喂，只拍这个框框里的东西就行了，框外面的不用管！”

- 如果你的取景框设得太小：你的立方体有一半在框外面，那拍出来的“距离照片”上就只有一半立方体。结果就是，只有那一半立方体能投下影子，另一半的影子就被“剪”掉了，看起来很奇怪。

- 如果你的取景框设得太大：就像你用一张很大的相纸去拍一个很小的蚂蚁。蚂蚁在照片上只占了很小很小的一点，照片大部分都是空白。这会导致蚂蚁的细节非常模糊。同理，如果你把取景框设得比你的场景大很多，那分配给立方体的像素就很少，它的影子边缘就会变得像马赛克一样，很难看。

结论： 这个“取景框”必须不大不小，刚刚好把所有需要投射影子的物体都框住，这样拍出来的“距离照片”质量最高，影子效果最好。

#### 2. 为什么平行光的阴影要用“正投影相机”产生？

这和光源的类型有关。

- 平行光 (DirectionalLight)：它模仿的是太阳光。太阳离我们非常远，所以光线到达地球时，可以看作是互相平行的。它照出来的影子，没有“近大远小”的效果。

- 正投影相机 (OrthographicCamera)：这是一种没有“近大远小”透视效果的特殊相机，常用于工程制图。它看到的所有东西都是“平”的，不管远近，大小都一样。它的观察线也是互相平行的。

你看，这两者的特性是不是完美匹配？

为了模仿平行光那种“平直”的、没有透视的影子，我们在拍那张“距离照片”时，就必须用一台同样“平直”的、没有透视的正投影相机来拍。这样才能保证生成的影子是符合平行光物理规律的。

而像聚光源（SpotLight），它像手电筒一样，光线从一个点发散，有“近大远小”，所以它的 shadow.camera 就用普通的透视相机 (PerspectiveCamera)。



## 加强理解距离

场景：

一盏从天花板上垂直照下来的灯。

灯下面有一张桌子。

桌子下面是地板。

```tex
      💡 (灯)
       |
       |
    [======] (桌子)
       |
       |
----------------- (地板)
```

现在，我们来一步步看这两个“距离”到底是什么。

------

### 1. 什么是“幻灯片上的标准距离”？ (Shadow Map)

这个距离是在 渲染的准备阶段 生成的，我们可以叫它 “光源的视力表”。

1. 想象你就是那盏灯 💡，你从上往下看。

1. 你的视线里，有些地方看到的是 桌子，有些地方透过桌子旁边看到了 地板。

1. 你现在制作一张地图（这就是“幻灯片”或“阴影贴图”），记录下你视线里 碰到的第一个东西 的距离。

- 在正对着桌子的区域，你记录下 “灯到桌子的距离”（比如2米）。

- 在桌子旁边的区域，你记录下 “灯到地板的距离”（比如3米）。

这张记录着【在每个方向上，离我最近的物体有多远】的地图，就是 “幻灯片”。**它上面记录的 2米 和 3米 就是 “标准距离”。**

**所以，“标准距离”就是：从光源的视角看，在某个特定方向上，能碰到的第一个物体的距离。**

------

### 2. 什么是“我的距离”？

这个距离是在 正式渲染我们看到的画面时 计算的。

1. 现在，你不再是灯了，你是一个粉刷匠，负责给场景里的每个像素点上色。

1. 你的任务是给 地板 上的某一个点（我们称它为P点）上色。这个P点，正好在桌子的正下方。

1. 为了决定P点是被照亮还是在阴影里，你需要计算出 “P点到灯的距离”。

- 因为P点在地板上，所以这个距离就是 “灯到地板的距离”（也就是3米）。

**这个【当前正要上色的这个点，到光源的实际距离】，就是 “我的距离”。**

### 关键的对比时刻！

现在，对于桌子正下方的那个地板点P，我们有了两个数据：

1. “我的距离”：P点到灯的实际距离是 3米。

1. “幻灯片上的标准距离”：我们拿出之前做好的“幻灯片”，查找P点所在的方向，发现上面记录的“标准距离”是 2米（因为在这个方向上，灯先看到的是桌子）。

现在进行比较：

\> “我的距离” (3米) > “幻灯片上的标准距离” (2米)

这个不等式成立了！

它的物理意义是：

“我（P点）离灯有3米远，但是在我和灯之间的这条路上，有一个东西（桌子）在2米远的地方就已经挡住了光线！所以我肯定在那个东西的影子里。”

因此，渲染器判定：P点在阴影里，把它涂成暗色。

如果我们在给桌子旁边的地板点上色呢？

- “我的距离” = 灯到地板的距离 = 3米

- “幻灯片上的标准距离” = 灯到地板的距离 = 3米

- 比较：3米 > 3米？不成立。

- 结论：没有东西挡着我，我被照亮了！





# Three.js 平行光阴影渲染原理总结

Three.js 实现动态阴影的核心技术是 阴影贴图（Shadow Mapping）。这是一个高效的、基于图像的算法，可以看作一个两阶段的过程。

------

## 阶段一：深度图渲染 (The Depth Pass)

这是最关键的一步，发生在正式渲染之前。Three.js 会在内部执行以下操作：

1. 创建虚拟相机：在你的平行光 directionalLight 的位置，系统会放置一个虚拟的、看不见的 正投影相机 (OrthographicCamera)。这个相机就是代码中的 directionalLight.shadow.camera。

1. 定义渲染范围：这个虚拟相机的“视野”（一个长方体视锥），由你设置的这几行代码决定。它定义了哪些区域的物体需要被计算阴影。

```js
    // ...
    directionalLight.shadow.camera.left = -200;
    directionalLight.shadow.camera.right = 200;
    directionalLight.shadow.camera.top = 200;
    directionalLight.shadow.camera.bottom = -200;
    directionalLight.shadow.camera.near = 0.5;
    directionalLight.shadow.camera.far = 1000;
    // ...
```

只有落在这个长方体视锥内的物体，才有可能投射阴影。

1. **生成深度图：系统从这个虚拟相机的视角，对场景进行一次特殊的渲染。这次渲染不关心颜色或材质，只关心一件事：深度。它会生成一张纹理（即阴影贴图/深度图），其中每个像素存储的是从光源到其视野中最近的那个物体表面的距离。**

- 在这一步，只有代码中设置了 mesh.castShadow = true 的物体（比如你的立方体）才会被渲染到这张深度图上。

------

#### 阶段二：最终场景渲染 (The Shading Pass)

这是我们最终看到画面的过程。

1. 正常渲染：主相机 (camera) 开始按正常流程渲染场景。

1. 像素级阴影判断：当渲染器处理到某个可以接收阴影的表面（即设置了 mesh.receiveShadow = true 的平面）上的一个像素时，它会执行一次对比：

- A. 计算“当前像素到光源的实际距离”。

- B. 查询“深度图”：它会把当前像素的位置转换到光源的坐标系下，然后在第一阶段生成的深度图中找到对应位置，读取那里存储的“标准距离”（即该方向上离光源最近的物体的距离）。

- 对比 A 和 B：

- 如果 A > B，意味着当前像素和光源之间有别的物体挡住了光线，所以这个像素处于 阴影 中。

- 如果 A <= B，意味着没有遮挡，这个像素被 光照。

------

### 启用阴影的关键代码总结

要成功渲染阴影，必须在三个地方进行设置，缺一不可：

1. 渲染器层面：全局开启阴影计算功能。

```typescript
    renderer.shadowMap.enabled = true;
```

2. 光源层面：指定该光源需要产生阴影。

```typescript
    directionalLight.castShadow = true;
```

3. 物体层面：

- 指定哪些物体需要 投射 阴影 (.castShadow = true)。

- 指定哪些物体需要 接收 并显示阴影 (.receiveShadow = true)。

这个“先从光源视角拍一张深度快照，再回头比较距离”的两步法，就是 Three.js 阴影渲染的理论核心。
