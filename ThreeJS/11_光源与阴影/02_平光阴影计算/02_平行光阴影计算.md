# 平行光阴影计算

本章场景：平行光从 `(100, 100, 0)` 斜着照下来，地面是 400×850 的平面，7 个 50×100×50 的立方体沿 z 轴排开（z = -300 ~ 300）。

---

## 1. 阴影是怎么算出来的

**一句话结论：** 渲染器先站在光源的位置"拍一张照片"，记下每个像素离光有多远（这张照片叫**深度图**），然后再正常渲染。渲染时发现某个点比深度图里记录的更远，说明它被挡住了，就画成阴影。

**代入数字理解：** 光源在 `(100, 100, 0)`，照向原点。水平走 100、竖直走 100，所以光线是 **45°** 斜射。立方体高 100，影子就朝 -x 方向拉出 **100** 长。

```
步骤1：从光源视角渲染一次 → 得到深度图（每个像素离光多远）
步骤2：从相机视角正常渲染
步骤3：每个点和深度图比一比 → 更远 = 被挡住 = 画阴影
```

**坑：**
- 开了阴影，每帧要多渲染一遍场景，所以 Three.js 默认全部关闭，需要手动开启。

---

## 2. 阴影系统三要素（缺一不可）

**一句话结论：** 渲染器开阴影 + 光源开阴影 + 物体分配角色（谁投射、谁接收），少一个都看不到阴影。

**最小代码：**

```js
// ① 渲染器开启阴影
renderer.shadowMap.enabled = true;

// ② 光源产生阴影
directionalLight.castShadow = true;

// ③ 物体分配角色
cube.castShadow = true;     // 投射阴影：挡光的物体
plane.receiveShadow = true; // 接收阴影：影子落在它身上
```

**坑：**
- `receiveShadow` 最容易忘。立方体的阴影确实投出去了，但没有物体接收，就没地方显示。
- `castShadow` / `receiveShadow` 设在 **Mesh（物体）** 上，不是设在材质上。
- 物体多的时候用 `traverse` 批量设置：

```js
group.traverse((obj) => {
  if (obj.isMesh) {
    obj.castShadow = true;
    obj.receiveShadow = true;
  }
});
```

---

## 3. 接收阴影的物体

**一句话结论：** 接收者可以是任何 Mesh（平面、立方体、球体……），只要设置了 `receiveShadow = true`。通常用平面，因为它模拟的是地面。

**最小代码：** 两个立方体互相投影、互相接收

```js
const cube1 = new THREE.Mesh(geometry, material);
cube1.castShadow = true;    // 投射阴影
cube1.receiveShadow = true; // 也接收阴影

const cube2 = cube1.clone(); // clone 会复制 castShadow / receiveShadow
cube2.position.x = 80;
```

**坑：**
- `clone()` 会把 `castShadow`、`receiveShadow` 一起复制过去，克隆后不用再设一遍。

---

## 4. 阴影相机范围（核心）

**先说清楚：阴影范围是通过"阴影相机"来控制的。** 平行光自带一台相机 `directionalLight.shadow.camera`，专门用来拍算阴影用的"距离照片"。**这台相机的取景范围，就是阴影范围。** 下面设的 `left / right / top / bottom / near / far`，全都是设在这台阴影相机上。它和你自己 `new` 出来看场景的 `camera` 是两台不同的相机。

**一句话结论：** 平行光的光线互相平行，所以阴影相机是**正投影相机**（拍出来没有近大远小），取景范围是一个长方体。只有在这个范围里的部分能计算阴影。

- `left / right / top / bottom`：阴影范围在**光源视角**下的左右上下边界
- `near / far`：阴影范围沿光线方向的前后边界（从光源位置算起）

**最小代码：**

```js
directionalLight.shadow.camera.left = -200;
directionalLight.shadow.camera.right = 200;
directionalLight.shadow.camera.top = 200;
directionalLight.shadow.camera.bottom = -200;
directionalLight.shadow.camera.near = 0.5;
directionalLight.shadow.camera.far = 1000;
```

**代入数字算一遍：**

这里的左右上下是**光源视角**的方向，不是地面的 x/z。本章光源和目标的 z 相同（光线方向在 xy 平面内），这时：

- left / right 正好对应**世界 z 轴**
- top / bottom 对应一条斜轴 `(-0.707, 0.707, 0)`

光源在 z = -225 时，阴影范围覆盖的 z 范围：

- -225 - 200 = **-425**
- -225 + 200 = **-25**

| 立方体 z | 占据的 z 范围 | 在阴影范围里吗 | 有阴影吗 |
|---|---|---|---|
| -300 | -325 ~ -275 | 完全在 | 有 |
| -200 | -225 ~ -175 | 完全在 | 有 |
| -100 | -125 ~ -75 | 完全在 | 有 |
| 0 | -25 ~ 25 | 只贴着边界 | 无 |
| 100 / 200 / 300 | 25 ~ 325 | 不在 | 无 |

所以光源停在 z = -225 时，只有 3 个立方体有阴影。

> 📷 待补截图：光源在 z = -225 时，只有前 3 个立方体有阴影

**范围该设多大：**

```
范围太小 → 物体在阴影范围外 → 阴影被切掉或消失
范围太大 → 阴影贴图的像素被摊薄 → 阴影模糊、有锯齿
刚刚好   → 包住"投影的物体 + 影子落下的地方"
```

**坑：**
- 把 left/right/top/bottom 当成地面的 x/z 来设。它们是光源视角下的方向，光源位置一变，对应的世界方向也会变。
- 只设了左右上下，忘了 `far`：物体离光源超过 far，也算不出阴影。

## 5. 用 CameraHelper 看范围

**一句话结论：** 阴影范围靠"猜"很难调，用 `CameraHelper` 把阴影相机的取景范围画出来，一眼就能看出物体在不在里面。

**最小代码：**

```js
const cameraHelper = new THREE.CameraHelper(directionalLight.shadow.camera);
scene.add(cameraHelper);
```

**坑：**
- 调试完记得注释掉，不然线框会一直显示在场景里。

## 6. 阴影精度 mapSize

**一句话结论：** `shadow.mapSize` 是深度图的像素数，默认 512×512。像素越多阴影越清晰，但性能消耗越大。

**代入数字算一遍**（阴影范围宽 400）：

| mapSize | 每个阴影像素覆盖 | 宽 50 的立方体占几个像素 | 效果 |
|---|---|---|---|
| 128 | 400 / 128 ≈ 3.13 | 50 / 3.13 ≈ 16 | 明显锯齿 |
| 512（默认） | 400 / 512 ≈ 0.78 | ≈ 64 | 一般 |
| 2048 | 400 / 2048 ≈ 0.20 | ≈ 256 | 清晰 |

范围扩大到 ±300（宽 600）、mapSize 不变：600 / 512 ≈ 1.17，阴影变模糊。**范围和 mapSize 要一起调。**

**最小代码：**

```js
directionalLight.shadow.mapSize.set(1024, 1024);
console.log("阴影像素", directionalLight.shadow.mapSize); // 默认 512, 512
```

**坑：**
- 阴影有锯齿时只知道调大 mapSize，没想到先把范围缩小到刚好够用，这样更省性能。

> 📷 待补截图：mapSize 128 与 2048 的阴影边缘对比

## 7. 移动平行光（让阴影范围跟着走）

**一句话结论：** 平行光的方向由 `position → target` 决定。要平移光源又保持方向不变，就**同时移动 position 和 target**。target 要加入场景才能跟着移动。

**代入数字算一遍：** 想让阴影范围的边缘刚好对齐平面边缘

- 平面 z 方向半长：850 / 2 = 425
- 阴影范围半宽：right = 200
- 光源最远只能走到：425 - 200 = **225**，所以在 z ∈ [-225, 225] 之间来回移动

**最小代码：**

```js
scene.add(directionalLight.target); // target 加入场景

const zBoundary = planeZSize / 2 - directionalLight.shadow.camera.right; // 225
let lightZSpeed = 3;
directionalLight.position.z = -zBoundary;
directionalLight.target.position.z = -zBoundary;

function render() {
  // 同时平移 position 和 target，光照方向不变
  directionalLight.position.z += lightZSpeed;
  directionalLight.target.position.z += lightZSpeed;
  // 到达边界就反向
  if (
    directionalLight.position.z > zBoundary ||
    directionalLight.position.z < -zBoundary
  ) {
    lightZSpeed = -lightZSpeed;
  }
  renderer.render(scene, camera);
  requestAnimationFrame(render);
}
render();
```

**坑：**
- 只移动 position、不移动 target，光的方向会变，阴影就歪了。
- 用 `shadow.camera.right` 算 z 方向的边界，前提是 left/right 对应世界 z 轴（光源与目标 z 相同）。如果光源位置改成 `(100, 100, 50)` 这种，这个算法就不准了。

> 📷 待补截图：光源移动时阴影范围沿 z 轴扫过的效果

## 8. 完整的最小配置

```js
// ① 渲染器
renderer.shadowMap.enabled = true;

// ② 光源
const light = new THREE.DirectionalLight(0xffffff, 1);
light.position.set(100, 100, 0);
light.castShadow = true;
light.shadow.camera.left = -200;
light.shadow.camera.right = 200;
light.shadow.camera.top = 200;
light.shadow.camera.bottom = -200;
light.shadow.camera.near = 0.5;
light.shadow.camera.far = 1000;
scene.add(light);

// ③ 投射阴影的物体
const cube = new THREE.Mesh(
  new THREE.BoxGeometry(50, 50, 50),
  new THREE.MeshLambertMaterial()
);
cube.position.y = 25; // 抬高半个边长，别埋进地里
cube.castShadow = true;
scene.add(cube);

// ④ 接收阴影的物体
const plane = new THREE.Mesh(
  new THREE.PlaneGeometry(500, 500),
  new THREE.MeshLambertMaterial()
);
plane.rotation.x = -Math.PI / 2;
plane.receiveShadow = true;
scene.add(plane);
```

## 9. 阴影不显示？排查清单

```
□ renderer.shadowMap.enabled = true 了吗？
□ light.castShadow = true 了吗？
□ 投射物体 castShadow = true 了吗？
□ 接收物体 receiveShadow = true 了吗？ ← 最容易忘
□ 物体在阴影范围里吗？（用 CameraHelper 看）
□ 物体离光源超过 far 了吗？
□ 材质受光照影响吗？（MeshBasicMaterial 不受光照影响）
```
