# 工厂光源

本章场景：加载一个工厂模型（`工厂.glb`，约 2000 × 17 × 2000），给它加环境贴图，再用平行光给整个工厂配阴影，最后用 GUI 调试光源和阴影范围。

------

# 一、旧知识点梳理

## 1. 加载环境贴图（CubeTexture）

**一句话结论：** 环境贴图是 6 张图拼成的"立方体贴图"，用来模拟物体反射周围环境，让材质更真实。用 `CubeTextureLoader` 加载，**`load()` 返回的才是贴图**。

**最小代码：**

```js
import * as THREE from "three";

// 1. 创建加载器
const cubeTextureLoader = new THREE.CubeTextureLoader();
// 2. 设置 6 张图的公共目录
cubeTextureLoader.setPath("./环境贴图/");
// 3. 加载，接住返回值：这才是贴图
const textureCube = cubeTextureLoader.load([
  "px.jpg", "nx.jpg", "py.jpg", "ny.jpg", "pz.jpg", "nz.jpg",
]);
// 4. 设置颜色空间
textureCube.colorSpace = THREE.SRGBColorSpace;
```

6 张图的顺序是固定的：

| 文件 | px    | nx    | py    | ny    | pz    | nz    |
| ---- | ----- | ----- | ----- | ----- | ----- | ----- |
| 方向 | +X 右 | -X 左 | +Y 上 | -Y 下 | +Z 前 | -Z 后 |

**坑：**

- 把**加载器**当成贴图赋给 `material.envMap`。不会报错，但没有任何反射效果：

```js
// ❌ 错误：load() 的返回值没接住，envMap 拿到的是加载器
const textureCube = new THREE.CubeTextureLoader();
textureCube.load([...]);
obj.material.envMap = textureCube;

// ✅ 正确
const textureCube = cubeTextureLoader.load([...]);
obj.material.envMap = textureCube;
```

- 旧写法 `texture.encoding = THREE.sRGBEncoding` 在新版本（如 0.174）里已经删除，`THREE.sRGBEncoding` 是 `undefined`，写了等于没写。新写法是 `texture.colorSpace = THREE.SRGBColorSpace`。
- 6 张图的顺序写错，反射出来的环境会错位。

------

## 2. 把环境贴图应用到 GLTF 模型

**一句话结论：** 模型加载完后，用 `traverse` 遍历所有 Mesh，把贴图设置到每个 Mesh 的材质上。

- `material.envMap`：设置环境贴图，材质开始反射环境
- `material.envMapIntensity`：反射强度，默认 1

**最小代码：**

```js
import { GLTFLoader } from "three/examples/jsm/loaders/GLTFLoader.js";

const loader = new GLTFLoader();
loader.load("./工厂.glb", (gltf) => {
  gltf.scene.traverse((child) => {
    if (child.isMesh) {
      child.material.envMap = textureCube;
      child.material.envMapIntensity = 1;
    }
  });
  scene.add(gltf.scene);
});
```

**坑：**

- 加载是异步的，修改材质的代码要写在回调函数**里面**。写在外面时，模型还没加载完，遍历不到任何 Mesh。

------

## 3. 为什么要用 traverse

**一句话结论：** GLTF 模型是一棵树，Mesh 可能嵌套在好几层 Group 里。`traverse` 会访问每一层的每一个节点，配合 `isMesh` 判断，就能处理到所有真正渲染出来的部件。

GLTF 模型可以想成一个文件夹，里面有：

1. **多个 Mesh**：墙、屋顶、机器……每个都有自己的几何体和材质
2. **Group**：用来把相关的 Mesh 归在一起，Group 本身**没有** `material`
3. **其他信息**：灯光、相机、动画等

```
gltf.scene (Group)
  |
  +-- Factory_Building (Group)
  |   +-- Walls (Mesh)    <-- 要设置 envMap
  |   +-- Roof (Mesh)     <-- 要设置 envMap
  |   +-- Windows (Mesh)  <-- 要设置 envMap
  |
  +-- Machinery (Group)
      +-- Machine_1 (Mesh) <-- 要设置 envMap
      +-- Machine_2 (Mesh) <-- 要设置 envMap
```

只遍历 `gltf.scene.children`，拿到的是两个 Group，没有材质可改。`traverse` 不管嵌套多深都能访问到。

**最小代码：**

```js
gltf.scene.traverse((child) => {
  if (child.isMesh) {
    // 只对 Mesh 操作
  }
});
```

**坑：**

- 即使模型只有一个 Mesh，也建议用 `traverse`，这样代码换成任何模型都能直接用。
- 嵌套回调里变量名要区分开。比如外面叫 `params`、里面叫 `child`，都叫 `obj` 会读混。

# 二、GLTF 模型的阴影计算

给大模型配阴影，按这个顺序来：**开阴影 → 量尺寸 → 放光源 → 设范围 → 调试与提升质量**。

## 4. 开启阴影三件套

**一句话结论：** 渲染器、光源、Mesh 三处都要开启。GLTF 模型用 `traverse` 给所有 Mesh 批量设置。

**最小代码：**

```js
// ① 渲染器
renderer.shadowMap.enabled = true;

// ② 光源
directionalLight.castShadow = true;

// ③ Mesh：工厂里的部件互相遮挡，所以一般都设成既投射又接收
gltf.scene.traverse((child) => {
  if (child.isMesh) {
    child.castShadow = true;    // 自己挡光，产生影子
    child.receiveShadow = true; // 别人的影子能落在自己身上
  }
});
```

**坑：**

- `castShadow`、`receiveShadow` 设在 Mesh 上，不是设在材质上。

------

## 5. 用 Box3 量模型尺寸

**一句话结论：** 阴影范围要按模型尺寸来设，所以先用 `Box3`（能包住整个模型的最小长方体）量出模型有多大。

**最小代码：**

```js
loader.load("./工厂.glb", (gltf) => {
  const box = new THREE.Box3().setFromObject(gltf.scene);
  const size = box.getSize(new THREE.Vector3());
  const center = box.getCenter(new THREE.Vector3());
  console.log("模型尺寸（宽×高×深）：", size);
  console.log("模型中心：", center);
  console.log("X 轴范围：", box.min.x, "到", box.max.x);
});
```

本项目量出来工厂约 **2000 × 17 × 2000**。

**坑：**

- 要在 `load` 回调里量，模型加载完才有尺寸。

------

## 6. 光源要放得足够远（安全距离）

**要解决什么问题：** 阴影是从光源的位置往光的方向"拍一张距离照片"算出来的。照片从一个**起始面**开始拍：起始面穿过光源，和光线垂直。起始面**后方**的东西拍不到，也就算不出阴影。光源离工厂太近时，起始面会把工厂切成两半，一半有阴影，一半没有。

**这个值是什么：** 把整个工厂装进一个**以原点为球心的圆球**里。只要光源在球外面，不管光从哪个方向来，起始面都在球外，整个工厂都在它前方。这个球的半径就是**安全距离**。

- 工厂俯视是 2000 × 2000 的正方形，离中心最远的是 4 个角
- 中心到角的距离就是球的半径，约 **1414**（工厂高 17，可以忽略）

**用在哪里：** 决定光源放多远，也就是 `directionalLight.position` 的长度要大于 1414。

```js
directionalLight.position.set(1500, 900, 0); // 离原点 ≈ 1749 > 1414 ✓
```

**怎么算：**

1. **安全距离（球半径）**：中心到角，往右 1000、往前 1000，斜着过去 = √(1000² + 1000²) ≈ 1414 或者直接让 Three.js 算：

   ```js
   const box = new THREE.Box3().setFromObject(gltf.scene);
   const sphere = box.getBoundingSphere(new THREE.Sphere());
   console.log("安全距离", sphere.radius); // ≈ 1414
   ```

2. **起始面离原点多远**：光照向原点，起始面和光线垂直，所以起始面离原点的距离 = 光源离原点的距离

   - 光源 (100, 60, 0)：√(100² + 60²) ≈ 117 < 1414 → 起始面切进工厂 ✗
   - 光源 (1500, 900, 0)：√(1500² + 900²) ≈ 1749 > 1414 → 整个工厂在前方 ✓

3. **（了解）切口落在哪**：和光线角度有关。光线与地面夹角 θ，tan θ = 60 / 100 = 0.6；起始面与竖直方向的夹角也是 θ。从光源 (100, 60) 往下 60 到地面，水平偏移 60 × tan θ = 36，所以切口在地面 x = 100 + 36 = 136，x > 136 的部分没有阴影。

```js
// 检查光源是否在安全距离外
const SAFE = 1414;
console.log(directionalLight.position.length() > SAFE ? "安全" : "有部分工厂在光源身后");
```

**坑：**

- 只把阴影范围（left/right/top/bottom）设大，不把光源拉远：范围只是往两侧加宽，起始面不动，被切掉的那部分还是没有阴影。
- 1414 是**保险值**：光从任何方向来都够用。某个具体角度下实际需要的距离可能更小，但每个角度都去算太麻烦。
- 光源要**沿原来的方向**拉远（各坐标等比放大，如 (100, 60, 0) → (1500, 900, 0)），光的方向才不变。

> 📷 待补截图：侧视图——光源在 (100, 60, 0) 时起始面从 x = 136 切过工厂；拉远到 (1500, 900, 0) 后起始面离开工厂

> 📷 待补截图：斜俯视——光源在 (100, 60, 0) 时右边立方体没影子，拉远后全部有影子

## 7. 设置阴影范围（left / right / top / bottom / near / far）

**先说清楚：阴影范围是通过阴影相机 `directionalLight.shadow.camera` 来控制的。** 这台相机是平行光自带的，不是你看场景用的 `camera`。它的取景范围就是阴影范围，下面的属性都设在它身上。

**一句话结论：** 平行光的阴影相机是一台正交相机（`OrthographicCamera`，拍出来的东西没有近大远小）。`left/right/top/bottom` 决定它拍多宽多高，`near/far` 决定它沿光线方向拍多远。范围要刚好盖住模型。

**代入数字算一遍：**

| 参数                        | 取值                 | 依据                                                         |
| --------------------------- | -------------------- | ------------------------------------------------------------ |
| left / right / top / bottom | ±1415                | 光源会绕 y 轴转动，转到斜 45° 时要盖住对角线，所以取半对角线 |
| near                        | 1                    | 从光源前方一点开始拍                                         |
| far                         | ≥ 1749 + 1415 ≈ 3164 | 光源距离 + 半对角线 = 最远的点；留余量设 4000                |

原来示例里的 ±100 只盖住 200 × 200 = 40,000，占工厂 2000 × 2000 = 4,000,000 的 **1%**。

**为什么用半对角线，不用半宽：** 阴影范围的左右方向，总是和光的方向垂直。

- 光从正右边照过来（angle = 0）：左右沿着正方形的边，±1000（半宽）就够
- 光转到斜 45°：左右也斜过来，正对着两个角，中心到角是 1414，±1000 就够不着了，那两个角落没有影子
- 所以光源会转动时，按最远的角设 ±1415；光源固定不转，就按实际需要设

```js
const MODEL_HALF = 1000;                                // 半宽
const SHADOW_HALF = Math.ceil(MODEL_HALF * Math.SQRT2); // 半对角线 ≈ 1415
```

> 📷 待补截图：光源斜 45° 时，范围 ±1000 两个角落没影子 vs ±1415 全部有影子（俯视）

**最小代码：**

```js
const cam = directionalLight.shadow.camera;
cam.left = -1415;
cam.right = 1415;
cam.top = 1415;
cam.bottom = -1415;
cam.near = 1;
cam.far = 4000;
```

**坑：**

- 范围设得太小：大部分模型没有阴影。
- `far` 不够：离光源远的那一侧没有阴影。
- 光源离得太近：见第 6 节。

## 8. 改了阴影范围要手动更新（更新机制）

**要解决什么问题：** 阴影范围的 `left/right/top/bottom/near/far` 设在 `directionalLight.shadow.camera` 上。这是**平行光自带的阴影相机**，专门用来拍"距离照片"，不是你自己创建的那台 `camera`。**阴影相机的取景范围就是阴影范围**，所以更新阴影范围，就是更新这台相机。

|                  | 你的相机 `camera`              | 阴影相机 `directionalLight.shadow.camera` |
| ---------------- | ------------------------------ | ----------------------------------------- |
| 谁创建           | 你自己 `new PerspectiveCamera` | 平行光自带                                |
| 拍什么           | 屏幕上看到的画面               | 只拍"距离照片"，用来算阴影                |
| 取景范围决定什么 | 你能看到多大的画面             | 哪里能算出阴影                            |

**这个方法是什么：** 相机拍照时读的不是 `left` 这些属性本身，而是根据它们算好的取景结果（投影矩阵）。改了属性，取景结果不会自动重算。`updateProjectionMatrix()` 就是让相机按新属性重新算一遍。和 `window.onresize` 里改完 `camera.aspect` 要调 `camera.updateProjectionMatrix()` 是同一个道理。

**一句话结论：** 第一次设置阴影范围不用手动调；渲染开始之后再改，要调阴影相机的 `updateProjectionMatrix()`，辅助框也要 `update()`。

**什么时候会自动更新（three.js 0.174 源码确认）：**

- `new THREE.CameraHelper(camera)` 创建时，会自动调一次 `updateProjectionMatrix()`
- 渲染器第一次生成阴影贴图时，也会自动调一次

**什么时候必须手动更新：** 渲染开始以后再改范围，比如用 GUI 拖动。这时要做两步：

```js
cam.left = -500;
cam.right = 500;
cam.updateProjectionMatrix(); // ① 让阴影计算用上新范围
cameraHelper.update();        // ② 让辅助框跟着变
```

**坑：**

- 只调了 `updateProjectionMatrix()`，没调 `cameraHelper.update()`：**阴影已经按新范围算了，辅助框还是旧的**，看到的和实际对不上，非常迷惑。
- 调试时在文件末尾临时改范围，忘了删，结果覆盖了前面认真算好的值。

## 9. 可视化与提升阴影质量

**一句话结论：** 用 `CameraHelper` 看阴影范围画在哪里；用 `mapSize` 提高清晰度；用 `VSMShadowMap` 加 `radius` 让阴影边缘变柔和。

### 9.1 可视化

```js
const cameraHelper = new THREE.CameraHelper(directionalLight.shadow.camera);
scene.add(cameraHelper);
```

[image-20250703220956632](https://claude.ai/chat/README.assets/image-20250703220956632.png)

### 9.2 清晰度（精度）mapSize

**精度是什么：** 阴影贴图是一张 mapSize × mapSize 的"距离照片"，铺在阴影范围上。每个像素管着地面上的一小块（一格），这一格要么整块在阴影里，要么整块不在。**一格越小，精度越高，影子边缘越清楚。**

**代入数字算一遍：** 一格 = 范围宽度 ÷ mapSize

| 范围宽          | mapSize | 一格多大                |
| --------------- | ------- | ----------------------- |
| 2830            | 2048    | 2830 / 2048 ≈ 1.38 单位 |
| 2830            | 4096    | ≈ 0.69 单位             |
| 400（只盖局部） | 2048    | ≈ 0.20 单位             |

假设工厂里一台机器只有 6 大：

- 一格 1.38：机器只分到 6 ÷ 1.38 ≈ 4 格，影子是几层方块叠出来的
- 一格 0.20：分到 6 ÷ 0.20 = 30 格，边缘清楚

**取舍：** 范围要大到盖住整个工厂，但范围越大一格越大、影子越糊。可以：

- 把 mapSize 调到 4096（一格 ≈ 0.69，更耗性能）
- 把范围缩到关心的区域
- 接受远处糊一点，用 VSM + radius 把方块边缘柔化

> 📷 待补截图：mapSize 2048 下，范围 ±1415 与 ±200 时小机器的影子对比

```js
directionalLight.shadow.mapSize.set(2048, 2048); // 默认 512
```

### 9.3 柔和度 VSMShadowMap + radius

```js
renderer.shadowMap.type = THREE.VSMShadowMap; // 换一种阴影算法，边缘可以变柔和
directionalLight.shadow.radius = 3;            // 值越大，边缘越模糊
```

**坑：**

- 范围很大时只加 mapSize，性能消耗涨得很快。优先把范围缩到真正关心的区域。
- VSM 只是让阴影边缘变柔和，**和范围内外的亮度无关，也和光的衰减无关**（平行光本来就没有衰减）。

> 📷 待补截图：VSM + radius = 3 的柔和阴影边缘

## 10. GUI 调试光源与阴影范围

**一句话结论：** 光源位置用"水平距离 R + 角度 angle"控制，绕着工厂转；阴影范围用一个"范围半宽"滑块同时控制四个方向。每次改动都要更新对应的辅助对象。

**代入数字理解光源位置：**

- `x = R × cos(angle)`，`z = R × sin(angle)`，高度 y 固定
- R = 1500、angle = 0 → `(1500, 900, 0)`
- R = 1500、angle = π/2 → `(0, 900, 1500)`

**最小代码：**

```js
const lightPositionControl = { R: 1500, angle: 0 };

function updateLightPosition() {
  directionalLight.position.set(
    lightPositionControl.R * Math.cos(lightPositionControl.angle),
    900,
    lightPositionControl.R * Math.sin(lightPositionControl.angle)
  );
  directionalLightHelper.update(); // 光源辅助对象跟着更新
}
updateLightPosition();

const lightFolder = gui.addFolder("平行光调试");
lightFolder.add(lightPositionControl, "R", 0, 3000).onChange(updateLightPosition);
lightFolder.add(lightPositionControl, "angle", 0, 2 * Math.PI).onChange(updateLightPosition);

// 阴影范围：一个滑块控制四个方向
const shadowControl = { half: 1415 };
const shadowFolder = gui.addFolder("平行光阴影");
shadowFolder.add(shadowControl, "half", 50, 2000).name("范围半宽").onChange((v) => {
  cam.left = -v;
  cam.right = v;
  cam.top = v;
  cam.bottom = -v;
  cam.updateProjectionMatrix();
  cameraHelper.update();
});
```

**坑：**

- R 允许拉到 3000 时，far 也要跟着够：√(3000² + 900²) + 1415 ≈ 4547，所以 far 至少设 5000。
- 调节环境贴图强度的 GUI 要写在 `load` 回调里，模型加载完才有 Mesh 可改。
- `DirectionalLightHelper` 的大小要配合场景尺寸，2000 大的场景里设成 5 几乎看不见，可以设成 50。
